更新：2026-11-03（v0.47 软件收尾后）。**决定：本项目投 2027 中国大学生计算机设计大赛（4C）物联网应用类**；原“小组任务协同 + 智能排期引擎”保留为备选；**先单人做，12 月前组队**。国创赛不参加，华为命题仅作设计参考。

---

## 1. 作品定位

- **暂定名**：面向智慧办公的 Agent 安全网关与星闪近场确认系统
- **类别**：物联网应用
- **一句话**：Agent 在 PC 端网关里受五道闸管控，高危操作必须由持有 WS63 确认节点的人在场按键，确认结果用 HMAC 绑定操作内容并留审计。
- **技术栈**：Node 网关（PC，v0.9）+ WS63 双板（SLE）+ 可选 OLED/继电器
- **与命题的关系**：不参加国创赛；华为命题只作为需求与设计参考，材料写实际版本（OH 4.x/5.x 或不上板）

## 2. 为什么适合“物联网应用类”

- 有真实硬件实体：两块 WS63、按键、OLED/继电器
- 有近场通信：SLE 挑战-应答，不是纯软件弹窗
- 有物理执行：确认后继电器/门锁/LED 动作
- 有软件深度：五道闸、令牌、审计链、角色分级、三档评测
- 演示有记忆点：不在场拒绝 / 到场放行 / 重放拒绝 / 双人确认

### 评测口径（2026-11-02 定，真实模型 ×3 轮）

- **v0.42 最终口径（个人域拒绝）**：完整网关攻击得逞 **0/24 次运行**（8 条验证样本 ×3 轮）；主动拦截 12、未尝试 12、故障 0；正常完成 **18/18（100%）**，误拦 **0**。
- **v0.41 基线（个人域确认后放行）**：完整网关 1/24（4.2%）；拆开写**未确认即执行 0/24**、闸4模拟确认后执行 1/24（V-A2）、主动拦截 11/24、未尝试 10/24、故障 2/24。
- 三档对照：无防护 **62.5%（15/24 次运行）** → 仅提示词 **25.0%（6/24）** → 完整网关 v0.42 **0/24**。
- 材料写法：写「未确认即执行 0/24；v0.42 个人域外发 0 放行」。**不要**把 v0.42 的 0/24 说成「策略直接挡住 V-A2」——该轮 V-A2 模型未尝试，策略由确定性回归证明。
- **对外统一口径（2026-11-05）**：「本轮 8 条验证集攻击样本 ×3 轮 = 24 次运行，未确认即执行 0 次；
  按 8 条独立样本计 95% 上界约 31%，不代表真实世界 0%」。不要再写裸「攻击成功率 0%」。
- **2026-11-05 语料 v3 复跑**：验证集 20 条攻击 ×3 轮 = 60 次运行，**0 得逞**；8 条每轮被拦（24 次尝试 0 绕过），12 条模型未尝试；正常 17/18、误拦 0。端到端 95% 上界 13.9%，模型实际尝试的 8 条条件上界 31.2%，见 [70](70-验证集扩充与真实模型复跑-2026-11-05.md)。

### 如实标注的模拟与边界

- `shareScreen` / `transcribeAudio` 仍是**模拟输出**，不是真实投屏/ASR；运行时输出会标注「模拟」，材料不能写成已实现。
- **租户 = 登录用户名**，不是组织/企业；隔离是单机演示级，不宣称 SaaS 多租户（治理页已标注）。
- **多租户决策（2026-11-03）**：**不投入组织级多租户**。产品形态=单租户一部署；登录用户隔离仅用于单机多用户场景；材料如实写“单租户”，不把租户=用户名包装成企业多租户。
- 闸4 的 `nearfieldOnline` 是**模拟确认**；确认端当前是虚拟设备或手机局域网（非硬件），UI/报告按实际传输标注；WS63 上板并接入串口后才能宣称「物理锚点已验收」。
- 邮件收件箱**默认只读同步**：先读 `bodyStructure`，只下载选中的文本段（≤256KB，支持 base64/quoted-printable/字符集），不标已读、不执行邮件内容。
- **自动回信（v0.46）默认关闭**；开启需显式白名单，使用固定模板（不读来信正文/主题），按 Message-ID 去重并限速。该路径是**配置层预授权，绕过 WS63 确认**，材料必须单列，不能写成「所有外发都经物理确认」。
- **审计快照外部存储（v0.47）**：只做本地目录复制（另一块盘/挂载共享），sha256 清单只能证明副本与导出时一致；有写权限的人可同时改写文件和清单，**不宣称防篡改**，防篡改仍靠本地独立检查点。
- **工程质量口径**：`npm run lint` 是真实 ESLint（flat config + security 插件，0 error/0 warning）+ 自定义危险模式扫描；`typecheck:strict` 已开启 `strict: true`，覆盖 `faults`、`operation`、`audit-sign`、`ws63-protocol`（含 governance 依赖；逐步扩，不是全量）；测试按文件并行（连续 3 次稳定，~4s）；本地 `npm run ci` 与 GitHub Actions 均已通过，GitCode Actions 入口未开通。
- Docker/HTTPS：控制台默认只监听 `127.0.0.1`；容器端口只映射到回环，由 nginx/Caddy 终止 TLS；部署模板强制 `SAFE_OFFICE_AUTH=required`，首次部署必须先建管理员；不要把 7812 直接暴露公网。
