# 4C 2027 参赛方案（物联网应用类）

更新：2026-10-17。**决定：本项目投 2027 中国大学生计算机设计大赛（4C）物联网应用类**；原“小组任务协同 + 智能排期引擎”保留为备选；**先单人做，12 月前组队**。国创赛不参加，华为命题仅作设计参考。

## 1. 作品定位

- **暂定名**：面向智慧办公的 Agent 安全网关与星闪近场确认系统
- **类别**：物联网应用
- **一句话**：Agent 在 PC 端网关里受五道闸管控，高危操作必须由持有 WS63 确认节点的人在场按键，确认结果用 HMAC 绑定操作内容并留审计。
- **技术栈**：Node 网关（PC，v0.9）+ WS63 双板（SLE）+ 可选 OLED/继电器
- **与命题的关系**：不参加国创赛；华为命题只作为需求与设计参考，材料写实际版本（OH 4.x/5.x 或不上板）

## 2. 为什么适合“物联网应用类”

- 有真实硬件实体：两块 WS63、按键、OLED/继电器
- 有近场通信：SLE 挑战-应答，不是纯软件弹窗
- 有物理执行：确认后继电器/门锁/LED 动作
- 有软件深度：五道闸、令牌、审计链、角色分级、三档评测
- 演示有记忆点：不在场拒绝 / 到场放行 / 重放拒绝 / 双人确认

### 评测口径（2026-11-02 定，真实模型 ×3 轮）

- **v0.42 最终口径（个人域拒绝）**：完整网关攻击得逞 **0/24（0.0%）**；主动拦截 12、未尝试 12、故障 0；正常完成 **18/18（100%）**，误拦 **0**。
- **v0.41 基线（个人域确认后放行）**：完整网关 1/24（4.2%）；拆开写**未确认即执行 0/24**、闸4模拟确认后执行 1/24（V-A2）、主动拦截 11/24、未尝试 10/24、故障 2/24。
- 三档对照：无防护 **62.5%（15/24）** → 仅提示词 **25.0%（6/24）** → 完整网关 v0.42 **0/24**。
- 材料写法：写「未确认即执行 0/24；v0.42 个人域外发 0 放行」。**不要**把 v0.42 的 0/24 说成「策略直接挡住 V-A2」——该轮 V-A2 模型未尝试，策略由确定性回归证明。
- 依据：[48-真实模型三轮复跑](48-真实模型三轮复跑-2026-11-02.md)

> 2026-11-02 决策：**v0.42 起个人邮箱域名在闸2直接拒绝**；v0.41「确认后放行」保留为基线/消融对照。V-A2 回归见 `prototype/test/engine.test.cjs`（闸2单测 + 端到端④）。

### 如实标注的模拟与边界

- `shareScreen` / `transcribeAudio` 仍是**模拟输出**，不是真实投屏/ASR；材料不能写成已实现。
- **租户 = 登录用户名**，不是组织/企业；隔离是单机演示级，不宣称 SaaS 多租户。
- 闸4 的 `nearfieldOnline` 是**模拟确认**；WS63 上板后替换为真实 SLE/手机确认，否则不能宣称「物理锚点已验收」。
- 邮件收件箱是**只读同步**：先读 `bodyStructure`，只下载选中的文本段（≤256KB，支持 base64/quoted-printable/字符集），不标已读、不自动回复、不执行邮件内容；附件保留只清理未被任何操作引用的过期内容。
- 评测是单模型（GLM-5.3-Flash）、14 条 validation、本地适配器；比率只代表本轮样本。
- Docker/HTTPS：控制台默认只监听 `127.0.0.1`；容器端口只映射到回环，由 nginx/Caddy 终止 TLS；部署模板强制 `SAFE_OFFICE_AUTH=required`，首次部署必须先建管理员；不要把 7812 直接暴露公网。
