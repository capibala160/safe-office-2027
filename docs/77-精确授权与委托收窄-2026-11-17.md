# 精确授权与委托收窄（2026-11-17）

> 「用户批准一次之后，权限不能悄悄变大」：先核对现有系统已经做到的，再把真正缺的
> **委托收窄**补上——子 Agent 只能继承父授权的一个子集。
>
> 结论：委托签发新增「只能收窄」约束，8 条测试；全量 **631（629 通过 + 2 跳过）**、lint/strict 全绿。

## 1. 已有的部分（不重复造）

| 能力 | 位置 | 说明 |
|---|---|---|
| 批准绑定内容 | `operationHash` | 正文/收件人/附件哈希/账号/别名都进哈希，确认帧 MAC 绑定它 |
| 一次性 | `FulfillmentService.confirm` | 只接受 `frozen` → 第二次确认被状态拒绝 |
| 到期 | 同上 | `expiresAt <= now` 直接转 expired，必须重新生成 |
| 执行前内容复核 | `_assertAttachmentsIntact` / 发送前重算哈希 | 附件被换 → CONFLICT |
| 工具/文档/次数 | `CapabilityToken` | 工具白名单、文档白名单、TTL、总调用次数 |

缺口在**委托**：`DelegationService.issue` 原来不做任何收窄校验，子代理可以拿到
**更多动作、更长有效期、更大范围**的令牌——这等于「一次同意，层层放大」。

## 2. 委托收窄（本次实现）

`DelegationService.issue({ ..., parent })`：

| 约束 | 规则 |
|---|---|
| 父令牌可用 | 必须签名有效、未撤销、未过期，且 `parent.to === 子.from` |
| 动作 | 子 `actions` ⊆ 父 `actions`；新增动作直接拒绝（`不能扩大动作范围`） |
| 有效期 | 子 `expiresAt ≤ 父.expiresAt`；超过即拒绝（`不能延长有效期`） |
| 范围标签 | `scope` 按逗号/空白拆成标签；子标签 ⊆ 父标签 |
| 显式收窄 | 父令牌有标签时，子令牌**不能留空**（空 = 不限范围，视为扩大） |
| 无父令牌 | 行为不变（顶层签发不受影响） |

实现上把「签名/撤销/过期/主体」抽成 `_verifyBase`，`verify()` 仍负责动作覆盖；
签发子令牌时用 `_verifyBase` 复核父令牌，避免父令牌动作列表干扰。

范围标签大小写不敏感、去重；`scope` 目前是**声明式标签**，不是结构化权限。

## 3. 验证

新增 `prototype/test/delegation-narrowing.test.cjs` 8 条（6 条签发收窄 + 2 条执行期复核）：

1. 子集动作 + 更短 TTL + 子集标签 → 通过；子令牌不能执行父令牌未覆盖的动作；
2. 新增动作 → 拒绝；
3. 延长有效期 → 拒绝；
4. 新增范围标签 / 留空 → 拒绝；
5. 父令牌伪造、主体不符、已撤销、已过期 → 拒绝签发；
6. 无父令牌时保持原行为。

全量 **631（629 通过 + 2 跳过）**；`npm run lint`、`npm run typecheck:strict` 全绿。

### 3.1 执行期复核（同日补做）

规划期放行的步骤在 `planner` 里打**非枚举**标记 `delegationVerified`；
`runtime` 执行前用同一个 `delegationVerifier` **再验一次**：拒绝则写审计
`委托复核拒绝`、跳过该步（不产生副作用）。补 2 条测试：令牌失效 → 拦截且 `outbox=0`；
令牌有效 → 正常执行。

## 4. 边界（必须如实写）

- 委托在**规划期**验证一次；**执行期会再验一次**（见 §3.1）：规划放行的步骤带
  `delegationVerified` 标记，执行前重新调用验证器，过期/撤销即拦截该步；
- `scope` 只用于签发收窄，执行时不与具体操作比对；
- 审批范围仍以 `operationHash` 绑定单次操作；没有「一次批准、多次执行」的配额模型
  （本系统是单操作单确认）；
- 令牌 MAC 用进程内密钥，不是 HUKS/外部信任根；撤销集在内存。
