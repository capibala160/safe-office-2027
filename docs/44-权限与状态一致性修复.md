# 权限与状态一致性修复（v0.40.1）

> 第三轮审查发现 3 个已复现问题：发件核对越权、批准后发送失败仍报成功、
> 会话续期不落盘。本轮逐条修复并补回归测试。

## 1. 发件核对越权（高）

**问题**：`POST /api/outbox/:id/reconcile` 只做了角色校验，没有把登录身份传进服务层，
也没有检查记录归属。Bob 读 Alice 的操作是 404，但拿 outboxId 提交核对却返回 200，
能把 Alice 的发件记录改成 `sent`。

**修复**

- `server.cjs`：核对接口把 `userContext(req)` 的 actor/role 传进服务层（body 不能覆盖）。
- `ConsoleService.reconcileOutbox`：先取 outbox → 对应 operation，用 `_operationVisible`
  判定；**不存在或不可见统一 404**，不泄露他人记录是否存在。
- 路由仍限 `ROLE_STAFF`（员工/管理员/审计员）；设备助手 403。
- 管理员/审计员跨租户核对保持可用；`actor=null`（本地免登录演示）行为不变。

**测试**

- HTTP：Alice 发起外发 → 设备助手批准（unknown）→ Bob 读操作 404、提交核对 404 且状态未变 →
  设备助手核对 403 → Alice 本人核对 200。
- 服务层：Bob 抛"发件记录不存在"，Alice 成功，管理员跨租户成功。

## 2. 批准后发送失败仍报成功（中）

**问题**：`_completeChallenge` 在 `fulfillment.send` 返回 `failed`（邮件服务明确拒绝）或
`unknown`（超时/网络不确定）时，仍返回 `ok:true, outcome:'approved', "设备已批准并执行"`；
手机确认端按 `data.ok` 展示"已确认，动作已发出"。

**修复**

- 发送结果不是 `sent` 时返回：
  - `failed` → `ok:false, outcome:'approved-but-failed', code:'SEND_FAILED'`
  - `unknown` → `ok:false, outcome:'approved-but-unknown', code:'SEND_UNKNOWN'`
  - 操作/outbox 状态、错误信息原样带上；挑战历史记 `SEND_FAILED/SEND_UNKNOWN`。
- 手机端 `confirm.js` 增加"已确认，但结果待核实"分支；设备页结果映射补两条错误态。
- 只有 `sent` 才返回 `ok:true`。

**测试**：拒绝邮件 → approved-but-failed、操作/outbox 均 failed；
超时邮件 → approved-but-unknown、outbox unknown。HTTP 测试同时断言 `ok:false`。

## 3. 会话续期不落盘（中）

**问题**：`verify()` 用"新过期时间 − 本次请求前的过期时间"与 60s 比较。
请求间隔一直小于 1 分钟时，差值永远达不到阈值，滑动续期从不写文件；
缩短 TTL 时重启会直接丢会话。

**修复**

- 每个会话记录 `persistedExpiresAt`（文件里实际写下的过期时间），登录/加载/每次成功落盘时维护。
- 续期落盘条件改为 `新过期时间 − persistedExpiresAt ≥ interval`；
  `interval = min(60s, max(1s, ttl/4))`，默认 8h TTL 下仍是每分钟最多写一次，
  短 TTL（测试/定制）按 TTL/4 缩小。
- 落盘失败时 `persistedExpiresAt` 不前进，下次请求继续尝试。

**测试**

- 每 20 秒访问一次、持续 2 分钟（相邻差远小于 60s）：续期必须写回文件，重启后有效。
- 短 TTL=4s：登录 → 3s 续期 → 4.5s 重启，会话仍有效（修复前文件里还是登录时的过期时间）。

## 4. IMAP 退信真实链路验证（补充）

- AWS SES 模拟地址 `bounce@simulator.amazonses.com` 实际发送成功，但 **8 轮轮询（约 2 分钟）
  没有收到任何退信**，INBOX/Junk 均无——该地址对非 SES 发信方未回 DSN。
- 12 位不存在的 QQ 号 `999999999999@qq.com`：QQ SMTP **同步 550 拒绝**
  （"The recipient may contain a non-existent account"），发送直接 `failed`，不会产生 DSN。
  这是"明确失败"路径，不是退信。
- 改用真实 QQ IMAP：创建临时文件夹 `SafeOfficeTest`，APPEND 一封**合成 DSN**
  （引用真实发送得到的 Message-ID），用真实 IMAP 连接取信/解析/回填/标已读；
  `outbox` 正确变为 `bounced`，审计记 `退信`，审计链有效；测试文件夹已删除。
- 口径：IMAP 取信与回填链路是真实的，本轮的 DSN 内容是合成的。
- **后续（v0.40.2）**：真实 Gmail 退信已到达（QQ 邮箱，2026-10-31 11:13），
  并暴露出 QQ 退信格式、Message-ID 改写、已读邮件漏扫三个问题；修复与真实回填结果见
  [QQ 退信兼容与真实回填](45-QQ退信兼容与真实回填.md)。

## 6. 边界

- 发件核对统一按 404 隐藏存在性；日志/审计里仍会记录操作者。
- `approved-but-failed/unknown` 之后重发必须新建操作，不能复用旧记录。
- 会话落盘仍是"最多每分钟一次"（默认 TTL）；进程在两次落盘之间被杀，最多丢约 1 分钟续期。
- 真实 MTA 退信已在 v0.40.2 完成验证（QQ 收 Gmail 退信）；QQ 格式/幂等键/已读漏扫的
  边界见 [QQ 退信兼容与真实回填](45-QQ退信兼容与真实回填.md)。
- 当前账号主动造退信仍不可控：SES 模拟地址不回信、QQ 对不存在账号同步 550。
