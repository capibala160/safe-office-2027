# 继电器 / 锁体支持（2026-11-05）

> 补上 [65](65-设备联动真板执行-2026-11-04.md) 的物理边界：设备执行此前只能驱动
> IO13 LED / IO10 蜂鸣器，**没有继电器与锁体**。本轮把 IO12 开成继电器输出，
> 主机侧加 `relayPin` 选项与 `SAFE_OFFICE_ACTUATOR_RELAY_PIN` 开关；
> 默认关闭，现有 LED 演示行为不变。
>
> 状态（2026-11-05 晚）：**固件已烧录并真机验证 IO12 翻转**（ACK `pin=12 level=1/0`），
> 主机 589 项测试（587 通过 + 2 跳过）全绿；**尚未接继电器与锁体**——没有实物前，仍不宣称「真实开锁」。

## 1. 硬件

| 件 | 规格 | 说明 |
|---|---|---|
| 继电器模块 | **3.3V 触发**、1 路、常开 | 5V 模块需三极管/MOSFET 驱动，不要直接接 GPIO |
| 电磁锁 / 电插锁 | 12V，1–2A | 门禁一般选**断电上锁**（fail-secure） |
| 12V 电源 | ≥1A | **锁不能从开发板取电** |
| 续流二极管 | 1N4007（或 1N5819） | 并联在锁线圈两端，阴极接 +12V |
| 杜邦线/端子 | — | 建议锁回路用螺丝端子，不飞线 |

接线：

```text
板 3V3  ── VCC(继电器)
板 GND  ── GND(继电器) ── 12V 电源负极（共地）
板 IO12 ── IN(继电器)
12V +   ── COM(继电器)
NO(继电器) ── 锁 +
锁 −    ── 12V 电源负极
二极管：跨接锁 + / 锁 −（阴极→+）
```

> 安全：不要把 220V 市电接进继电器做演示。用 12V 适配器；锁回路与板子共地；
> 上电前先断开 12V，确认 IO12 默认低（继电器不吸合）。

## 2. 固件改动（`ws63/firmware/board-confirm/board_confirm_m3.c`）

- 新增 `PIN_RELAY = GPIO_12`，`actuator_pin_allowed()` 放行 IO12（仍保留 IO13/IO10）
- 上电初始化 IO12 为输出低（继电器不吸合 = 上锁），串口打印 `SFC1 relay: IO12 idle LOW`
- 执行帧打到 IO12 时，**同步点亮 IO13** 做状态指示（现场不接锁也能看到结果）
- IO12 从按键候选脚列表移除（KEY2 仍是 IO3，不受影响）

### 3.1 语义与 fail-closed（v0.52.3 加固）

- 继电器只在**设备名是门锁类**（含「锁 / 门禁 / 门」或 `door` / `lock`，如「会议室-门锁」「front-door」）
  且操作是 `unlock` / `open` / `lock` / `close` 时才动作。
- 通用 `on` / `start` / `off` / `stop` 仍只驱动 IO13 LED——**开灯、开空调不会误触门锁继电器**。
- 继电器模式下，门锁类判断不通过时直接返回「没有映射到物理动作」，**不写串口**（fail-closed）。
- `relayPin` 只接受 IO12 / IO13（固件实际放行的输出脚）；配成 IO10 或其他脚会在启动时报错，
  不会把「开锁」变成蜂鸣，也不会发一个板端必拒的帧。
- 单板只有一路继电器：所有门锁类设备共用一个锁脚；多门需要多板/多路扩展。

用法：

```bash
# .env / config.env
SAFE_OFFICE_ACTUATOR_RELAY_PIN=12

# 或命令行单测执行（不经过控制台）
node scripts/actuator-probe.cjs --port COM11 --pin 12 --level 1   # 吸合（开锁）
node scripts/actuator-probe.cjs --port COM11 --pin 12 --level 0   # 释放（上锁）
```

默认不配 `SAFE_OFFICE_ACTUATOR_RELAY_PIN` → `unlock/lock` 仍驱动 IO13 LED，
与 [65](65-设备联动真板执行-2026-11-04.md) 的行为完全一致。

## 5. 回归提醒

- 烧完整 `ws63-liteos-app_all.fwpkg` 会写 `ws63_all_nv.bin`，**配网钥匙与 nonce 窗口会被清掉**，
  烧完必须重新配网（见 [57](57-M3板端SFC1与串口CLI-2026-11-04.md) 与 [10](10-硬件上手记录.md)）。
- 继电器模块务必选 3.3V 触发；5V 模块经分压/三极管后再接 IO12，否则可能拉低 GPIO 或损坏板子。
- 业务设备名必须含「锁 / 门禁 / 门」或 `door` / `lock`，否则继电器模式下会明确拒绝（fail-closed）。
  例如 `--lock-device ws63-A` 不会动作；应使用「会议室-门锁」这类名字。
  v0.52.3 之前用 `--device ws63-A` 跑继电器模式的命令需改用默认 `--lock-device 门锁`
  （`--device` 仍是板端身份，不再兼任业务设备名）。
- **主机崩溃/退出不会自动回锁**：当前没有板端自动回锁，`unlock` 后继电器会保持吸合直到收到 `lock`。
  演示结束前务必确认执行过 `lock`（或断电——断电上锁是锁体属性）。板端超时回锁尚未实现。
