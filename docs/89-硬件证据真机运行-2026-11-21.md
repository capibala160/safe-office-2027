`COM12→ws63-B`、`COM11→ws63-A`/`ws63-B` 均 PONG，确认后使用正确拓扑。
以后每次插拔都先跑 PING，不要盲信历史 COM 号。

## 2. 预检

1. `link:verify --a COM12 --b COM11`：心跳双向在跑（seq=479），但因未在窗口内复位，
   启动期 `init role`/`ALIVE` 日志未捕获 → 判 FAIL；**不是链路故障**。
2. 单轮 `serial-confirm --port COM11 --device ws63-B --actuator-device ws63-A`：
   B 短按 → `decision=1 device=ws63-B`，A `status=0 pin=12 level=1`，随后 `level=0` 复位成功。

## 4. 运行中发现并修复的问题

- 取消/超时的“确认失败：DECISION/TIMEOUT …”输出走 **stderr**，一键脚本最初只解析 stdout，
  导致 5 轮取消被误判为失败。修复为 `stdout + stderr` 一起解析；
  **这 5 条解析器误判记录已从证据包剔除**（不是硬件失败），修复后重跑取消 **5/5**。
- 端口对调导致第一次预检把执行帧发给了确认端 B（`ACTUATOR_TIMEOUT`）；
  PING 识别后改用 A=COM11，预检通过。

## 5. 边界（与结果一起写）

- **ACK ≠ 开锁**：只证明“确认 → 执行帧 → 执行端 ACK”；本次**未录视频、未做锁舌目视记录**。
- **锁舌为隐藏式（2026-11-21 用户说明）**：后续视频不拍锁舌特写，也不写“目视锁舌动作”；
  改用 **继电器指示灯 + 咔哒声 + 锁体线圈电流脉冲 + 门体开合（若已安装）** 作为物理证据。
- **不装续流二极管**（2026-11-21 拍板）：感性反电动势无抑制，属演示级残余风险。
- 锁体由**板载 5V/USB** 驱动；无保险丝；不接市电；不宣称门禁认证/可靠开锁/距离证明。
- 时延含人工反应，不是纯系统时延；重复运行只说明稳定性，不增加独立样本量。
- 篡改/重放直接打确认端 B；SLE 中继链路的异常路径另由 `sfc1:neg` 与 docs/74 覆盖。

## 6. 视频替代方案（锁舌隐藏版）

一镜到底建议顺序（手机横拍，30–60 秒）：

1. PC 端：操作已冻结，显示收件人/密级/操作哈希；
2. B 板 OLED：目标/密级/摘要三页；
3. 手指**短按** KEY2；继电器模块**指示灯亮 + 咔哒声**（特写）；
4. **串联电流表/万用表**（锁体 5V 供电回路）读数出现脉冲；若锁已装在门/盒上，拉门演示“通电开、断电锁”；
5. PC 端：`decision=1`、A `status=0 pin=12 level=1`、审计/回执。

证据组合：**继电器动作 + 电流脉冲 + 门体动作（可选）+ 执行回执**。
仍不宣称“可见锁舌动作”“安全门禁”或“距离证明”。
