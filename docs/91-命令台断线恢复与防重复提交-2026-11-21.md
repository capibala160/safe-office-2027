# 命令台断线恢复与防重复提交（v0.54.1，2026-11-21）

> 目标：任务提交后网络中断，页面不清空已收到的进度；连接恢复后按**原任务编号**继续查询；
> 取消按钮始终作用于**当前显示的任务**；提交没有收到服务器回执时**不自动重提**，
> 而是暂停并引导用户到工作台核对最近任务与待办。
>
> 本轮只改前端（`public/api.js`、`app.js`、`views.js`、`styles.css`）与 E2E；
> 服务端任务执行与幂等语义不变。

## 1. 行为

### 1.1 进度查询断线

- 每次查询 `GET /api/commands/<runId>` 带 **8 秒超时**（`AbortSignal.timeout`）。
- 仅对 **网络错误 / 502 / 503 / 504** 重试；404/400 等业务错误直接停下并显示原因。
- 退避 900ms → 1.8s → 3.6s → 5s 封顶；成功后重置为 900ms。
- **默认最多连续重试 60 次**（约 5 分钟）：超过后暂停自动重连，保留最后进度并显示
  「继续查询」按钮；用户可手动继续，不会被无限重试困住。
- 重试期间：
  - 页面**保留最后一次收到的阶段与步骤记录**，不清空；
  - 显示「暂时无法获取进度（第 N 次重试），连接恢复后会继续查询此任务。」；
  - 取消按钮禁用（避免对不确定状态发取消）。
- 连接恢复后继续查询**同一个 runId**，不新建任务、不重复提交。
- 离开页面（`target.isConnected === false`）后停止轮询。

### 1.2 取消按钮绑定当前任务

- 页面维护 `watchedRunId`，取消请求发到 `POST /api/commands/<watchedRunId>/cancel`。
- 不再读 `store.activeRunId`（它可能在刷新/恢复后为空或指向别的任务）。
- 取消请求进行中禁用按钮，防止重复点击。

### 1.3 提交未收到回执

- 提交前置 `submissionUncertain=true`；只有 `startRun` 成功返回 runId 才清为 false。
- POST 带 **15 秒客户端超时**（`AbortSignal.timeout`）；超时与网络中断一样按“未收到回执”处理。
- 若 POST 抛 **网络错误、超时或 5xx**：
  - 不自动重试、不再次提交；
  - 运行/清空按钮保持禁用；
  - 显示「未收到提交回执。请在连接恢复后查看工作台的最近任务及待办，核对是否已经接收。」+ 工作台链接。
- **仍需人工确认服务器是否已接收任务**——页面不替用户判断“没成功”。

### 1.4 回到页面恢复任务

- `#/command?run=<runId>`、`store.activeRunId`、`localStorage.safe-office.activeRun` 三者取一个，
  统一走 `watch(runId)`；已完成的任务取一次快照后渲染结果。

## 2. 验证

新增 E2E：

1. **「任务状态查询断线后恢复，提交只发生一次」**
   - 拦截 `POST /api/commands/async` 计数：全程 **submissions=1**；
   - 第一次 `GET /api/commands/RUN-*` 用 `route.abort('internetdisconnected')` 模拟断线；
   - 断言：出现重连提示、运行/取消按钮禁用、恢复后仍查询**同一个路径**
     （`Set(paths).size === 1`，查询次数 ≥2）、最终操作卡片出现且运行按钮恢复。
2. **「提交超时未收到回执 → 暂停重提并引导工作台」**
   - 注入 `window.SAFE_OFFICE_POST_TIMEOUT_MS = 300`，POST 路由延迟不返回；
   - 断言：出现「未收到提交回执」+ 工作台链接、`submissions=1`、运行/清空按钮禁用。
3. **「多次查询失败后暂停自动重连，可手动继续」**
   - 注入 `window.SAFE_OFFICE_POLL_MAX_RETRIES = 2`，GET 持续断线；
   - 断言：出现「自动重连已暂停」+「继续查询」、运行按钮禁用、进度未被错误页覆盖；
   - 恢复网络后点「继续查询」→ 操作卡片出现、运行按钮恢复可用。

## 3. 边界与残余风险

- **提交超时仍是“不确定”，不是“失败”**：15 秒只是客户端放弃等待；服务器可能已经接收任务。
  页面不会自动重提，必须到工作台核对——这是有意设计，不能用“重试”掩盖。
- 轮询默认 **60 次后暂停**（约 5 分钟），用户可手动「继续查询」；不会无限占用页面，
  也没有离线队列/后台自动重提。
- 断线期间任务仍在服务端执行；恢复后最新快照包含**完整 `stageLog`**，页面会一次性补齐阶段记录；
  只有非 stageLog 的瞬时 UI 行（如逐行日志动画）不会补播。
- 本轮不改变服务端幂等键与任务编号语义；同一 runId 重复查询只读。
- E2E 用浏览器路由模拟断线/超时，不覆盖真实网络切换（Wi-Fi 断开/代理抖动）。
- 测试专用注入：`window.SAFE_OFFICE_POST_TIMEOUT_MS`、`window.SAFE_OFFICE_POLL_MAX_RETRIES`
  仅用于缩短 E2E 等待，生产默认 15s / 60 次。
