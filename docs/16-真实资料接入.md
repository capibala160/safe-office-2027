# 真实资料接入（v0.16）

> 2026-10-29 建立。第一版范围：**导入 → 起草 → 手机确认 → 复制/下载已批准正文**。**不接真实发送**，`FakeMailer` 继续兜底。

---

## 1. 为什么先做「本地文档/会议纪要」

- 数据是使用者自己的，不牵扯第三方个人信息；`.eml` 导出天然带别人的姓名、邮箱、正文。
- 与现有场景同一条线（会议纪要），换成真实资料后五道闸、溯源、确认闭环的行为可直接对照。
- 不需要邮箱凭据、发件域名和退信处理。

**前提约束**：不得导入真实企业机密；真实资料只落本地库，绝不入库、不进云模型（机密正文由 `model-boundary.cjs` 拦在端侧）。

---

## 2. 怎么用

```bash
cd prototype

# 想用真实模型：复制模板填三项（config.env 已 gitignore，不会进仓库）
cp config.env.example config.env && notepad config.env

# 启动（Windows 也可直接双击 启动.bat）
npm start

# 导入（密级必须显式给：公开 / 内部 / 机密）
npm run import -- "C:\path\周例会纪要.md" --level 内部

# 查看已导入
npm run import -- --list

# 删除
npm run import -- --remove IMP-xxxxxxxx

# 启动控制台，导入的资料出现在「文件」页，并进入角色可读集合
npm start
```

- 支持 `.txt` / `.md` / `.docx`（docx 走最小 ZIP 解析，只抽 `word/document.xml` 的正文；批注、修订、图片、表格样式会丢）。
- 单文件上限 5MB。
- **id 由文件内容哈希派生**（`IMP-<sha256 前 8 位>`）：同一份文件重复导入不会产生副本，只更新密级。
- 库文件：`prototype/data/documents.db`，已在 `.gitignore`（`prototype/data/`），不会随仓库走。

| 层 | 改动 | 说明 |

| 文档视图 | `scenario.cjs` 新增 `registerDocuments / allDocuments / getDocumentById` | 样例 `DOCS` 保持静态，导入资料并入同一视图 |

## 6. 生成稿绑定（同日补上的规则闸）

| 项 | 内容 |
|---|---|
| 规则 | 同一计划里出现 `summarize(of=X)`，则任何**直接发送源文档 X** 的步骤被移除，必须发送 `draft_X` |
| 位置 | `planner.cjs` 的 `validatePlan`；排在「收件人溯源」检查之后（收件人本身未授权时，先报来源问题更准确） |
| 为什么不自动改写 | 把 `docId` 悄悄改成 `draft_X` 等于替模型改意图；**移除并留证据**更安全 |
| 不触发的情况 | 计划里没有 summarize —— 用户就是让把原件发给对方，属于合法路径 |
| 测试 | `attacks.test.cjs` 2 项：发送源文档被移除；`draft_M2` 与无 summarize 场景不受影响 |

## 5. 没做的（照实写）

- **真实发送**：`FakeMailer` 不变，没有 SMTP/邮箱 API；导出的是文本，不是"发出去了"。
- **起草仍是模型自由发挥**：导入资料只解决"有真实输入"，任务与草稿的对应关系仍由模型决定。
  - 但「发信必须引用生成稿、不能发源文档」已从提示词升级为**代码强制**（§6）。
- **docx 抽取很浅**：表格会连成一行，页眉页脚、脚注、批注都读不到。
- **docx 解压有硬上限**（2026-10-29 补）：单条目声明解压后 ≤10MB、总量 ≤20MB、条目数 ≤200；解压时再用 `maxOutputLength` 硬截断一次，防压缩炸弹。注意：这些是**防内存打爆**的上限，不是内容安全扫描。
- **没有做去重之外的版本管理**：同 id 再次导入会直接覆盖，旧版本不留。

## 7. 附件链路（同日）

| 项 | 内容 |
|---|---|
| 存储 | `src/blob-store.cjs`：按内容 sha256 寻址，落在 `prototype/data/attachments.db`（已 gitignore）；同一份文件重复上传只存一份 |
| 冻结 | 外发/内发邮件操作把 `{name, sha256, size}` 写进冻结记录，`attachmentHashes` 一并进 `operationHash` |
| 执行 | 每次发送前重算附件内容哈希；内容被换或缺失 → `CONFLICT`，拒绝执行（统一走 `_sendChecked`） |
| 下载 | `GET /api/operations/:id/attachments/:sha`，**批准后**才可用；下载前同样校验冻结记录与内容哈希 |
| 界面 | 命令台可挂附件（≤5 个）；操作卡片在批准后把附件名变成下载链接 |
| 限制 | 单个 ≤5MB、总计 ≤10MB、最多 5 个；只随邮件操作冻结，删除/打印/设备操作不带附件 |
| 测试 | `test/attachments.test.cjs` 6 项：冻结元数据、非邮件不带、内容篡改拒绝、内容缺失拒绝、批准前后下载、入参校验 |

**配置**：`config.env` 里写 `SAFE_OFFICE_LLM_ENDPOINT/KEY/MODEL`（OpenAI 兼容），可选 `SAFE_OFFICE_LLM_TIMEOUT_MS`（默认 60000）；**已存在的环境变量优先**，命令行临时设置不会被文件覆盖。启动横幅会打印实际模型与配置来源，**不会打印 key**。

**没做**：不做病毒扫描与加密；`reset()` 后附件库里的孤儿内容不清理；`FakeMailer` 只记录附件元数据（`HttpMailer` 会带上 `op.attachments`，但没有真实邮件服务接收）。

## 8. 真实模型联调记录（2026-10-29）

第一次接真实模型（智谱 `glm-5.3-flash`）踩到的三件事，都已修：

| 现象 | 根因 | 处理 |
|---|---|---|
| 3 步计划全被判「非法动作」 | 模型输出 `{"tool","params"}`，而约定是 `{"action","args"}`；提示词只列了工具名，没写字段名 | `PLAN_SYSTEM_PROMPT` 显式规定 `action/args/reason`，并禁止别名字段 |
| 规划失败：模型超时 | `HttpLLM` 默认 15s，带推理的模型一次规划要几十秒 | 默认提到 60s，可用 `SAFE_OFFICE_LLM_TIMEOUT_MS` 覆盖 |
| 单次规划 39s | 模型带推理链，token 多 | 演示想快就换更轻的模型（改 `SAFE_OFFICE_LLM_MODEL`） |

**联调结论**：真实模型下「读文档 → 生成正式稿 → 内网邮件自动确认 → 发送」整条链跑通，`模型边界` 审计显示 M2 正文脱敏后送云、机密 0 篇分流。**仍未做真实模型评测跑分**。
