# WS63 优先方案（双板星闪近场确认）

更新：2026-10-17。**路线决定：先做 WS63，买/借到 RK3568 再考虑上板；项目定位为 4C 2027 物联网应用类 + 毕设（不参加国创赛）。**

> 目标：用两块 WS63 做出“高危操作必须由持有设备的人在场按键确认”的可演示闭环。
> 不追求完整 Agent 网关；把“物理锚点”这一件事做扎实。

---

## 1. 范围

### 做

- 双板 SLE 链路（执行端 ↔ 确认端）
- 挑战-应答：nonce + 操作哈希 + 过期时间 + HMAC
- 按键确认/取消；LED/蜂鸣器/OLED 指示
- 本地策略表（3–5 条：放行 / 确认 / 拒绝）
- 审计环形缓冲（Flash，最近 N 条；串口导出）
- 攻击演示：不在场 / 取消 / 重放 / 篡改 / 错设备

### 不做

- LLM 调用、文档解析、图片/语音处理
- ArkTS / 标准系统 UI
- HUKS / TEE（WS63 轻量系统通常不提供；密钥存 Flash，保护级别有限，以实际 SDK 为准）
- 完整五道闸、治理面板、角色分级（这些留在 Node 原型）
- 防中继、距离证明、本人身份认证（SLE 连通/RSSI 不构成这些保证）

## 2. 系统组成

```
WS63-A 执行端（网关模拟）                 WS63-B 确认端（持有者）
┌──────────────────────┐   SLE 链路   ┌──────────────────────┐
│ 任务/策略表           │ ──────────> │ OLED/LED 显示操作摘要 │
│ nonce + 操作哈希      │ <────────── │ 按键：确认 / 取消      │
│ 验 HMAC/过期/重放     │             │ HMAC 响应             │
│ 执行模拟动作 + 审计   │             └──────────────────────┘
└──────────────────────┘
```

- 两板烧同一套固件，用角色开关区分 A/B
- 可选：A 接继电器/LED 模拟“物理动作”；B 接 OLED 显示操作内容

## 3. 协议 v0.1（二进制定长帧）

### 3.1 帧头（10 字节）

| 字段 | 长度 | 说明 |
|---|---|---|
| magic | 4B | `SFC1` |
| version | 1B | 0x01 |
| type | 1B | 0x01 CHALLENGE / 0x02 DECISION / 0x03 HEARTBEAT / 0x04 ERROR |
| flags | 1B | 保留 |
| reserved | 1B | 0 |
| length | 2B | 负载长度（小端） |

### 3.2 CHALLENGE（A → B）

| 字段 | 长度 | 说明 |
|---|---|---|
| taskId | 8B | ASCII/十六进制，A 生成 |
| nonce | 16B | 随机数，一次性 |
| action | 1B | 1=外发 2=删除 3=打印 4=设备控制 |
| targetHash | 32B | SHA-256(操作摘要) |
| issuedAt | 4B | Unix 时间（秒） |
| expiresAt | 4B | 建议 30s |
| summaryLen | 1B | ≤ 96 |
| summary | ≤96B | UTF-8，供 B 显示 |
| mac | 32B | HMAC-SHA256(前面所有字段, 预共享密钥) |

### 3.3 DECISION（B → A）

| 字段 | 长度 | 说明 |
|---|---|---|
| taskId | 8B | 回显 |
| nonce | 16B | 回显 |
| decision | 1B | 0=取消 1=确认 |
| deviceId | 8B | B 的设备标识 |
| decidedAt | 4B | Unix 时间 |
| mac | 32B | HMAC-SHA256(前面所有字段, 预共享密钥) |

### 3.4 A 的校验顺序（fail-closed）

1. 帧头/长度合法
2. `taskId` 与当前待确认任务一致
3. `nonce` 未被消费（重放拒绝）
4. `decidedAt <= expiresAt`（超时拒绝）
5. HMAC 校验通过
6. `decision == 1`（取消则拒绝）
7. 消费 nonce，执行动作，写审计

任何一步失败 → 不执行、红灯/蜂鸣、写审计。

### 3.5 密钥与随机数

- 预共享 32B 密钥，编译期写入两块板（演示用）；生产应改为安全分发/安全元件
- HMAC-SHA256 / SHA-256 用 SDK 自带的 mbedTLS/crypto 库（以实际 SDK 为准）
- nonce 用 SDK 随机源；若只有伪随机，需在文档中如实标注
- **边界**：密钥在 Flash，能读固件就能读密钥；这不是 HUKS/TEE 级保护

| 里程碑 | 内容 | 通过标准 | 预估 |
|---|---|---|---|
| **M0 环境** | 识别板型；HiSpark Studio 或 WSL；SDK 拉取；点灯 + 串口 | 串口能看到 printf；LED 可控 | 2–4 天 |

## 6. 演示脚本（6 场）

1. **正常**：A 发起“外发纪要” → B 显示摘要 → 按键确认 → A 绿灯/继电器动作 + 审计
2. **不在场**：B 不在/不响应 → A 超时拒绝、红灯
3. **取消**：B 按取消 → A 拒绝
4. **重放**：把旧 DECISION 再发一次 → nonce 已消费 → 拒绝
5. **篡改**：改 summary/targetHash → HMAC 失败 → 拒绝
6. **错设备**：换一块密钥不同的板 → HMAC 失败 → 拒绝

## 7. 风险与边界

- **板型/SDK 不确定**：先拍照/看丝印确认型号，再决定 HiSpark Studio 还是 WSL 路线（见 `docs/01`）
- **SLE API 复杂度**：用官方 SLE 示例起步，不要从零写协议栈
- **Flash 寿命/容量**：审计用环形缓冲，控制写入频率
- **通常无 HUKS**：密钥在 Flash；材料写“预共享密钥/软件保护”，不写“硬件密钥库”（以实际 SDK 为准）
- **SLE ≠ 距离证明**：不声称防中继、不声称本人身份认证
- **时间**：M2 卡住就先做单板 + 串口模拟确认，保证有可演示成果
