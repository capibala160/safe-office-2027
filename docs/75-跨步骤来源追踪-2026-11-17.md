# 跨步骤来源追踪（2026-11-17）

> 主线升级的第一刀：把「每条知识条目带 sourceIds」升级成**来源闭包**——
> 摘要、OCR、转写、生成稿之后，密级与污点仍然随内容走，出站/打印时按闭包核对。
>
> 结论：机制落地 + 附件来源闭包；新增 10 条测试（4 条来源闭包 + 6 条附件），
> 全量 **618 测试（616 通过 + 2 跳过）**、lint、strict 全绿。

## 1. 解决的问题

原有实现里，令牌和闸3只看**当前这一条**文档：

- `summarize` 生成的 `draft_X` 继承 `doc.level`，但闸3 只比较 draft 自身的等级；
- `tainted`（输入里检出注入、被隔离后产生的转写稿/识别稿）**只被记录，没有在出站时使用**；
- 令牌的源文档校验只沿一层 `sourceIds`，派生链更长时容易漏。

结果：**单步检查都合法，组合起来可能把受污染/高密级内容送出去**。

## 2. 机制

### 2.1 来源闭包 `_provenanceOf(id)`

沿 `sourceIds` 递归到根源（先去重、防环），返回：

```js
{ sources: [...根源id], maxLevel: '公开'|'内部'|'机密', tainted: boolean, transforms: [...] }
```

- 密级取链上**最高**（未知密级按最高处理，fail-closed）；
- 污点取链上**并集**；
- `transforms` 记录转换类型（`summarize` 等），为后续回放/审计留证据。

### 2.2 派生内容继承

`summarize` 生成 `draft_X` 时：

- `level = max(源等级, 派生前的等级)`——**转换不能降级**；
- `tainted = doc.tainted || 闭包.tainted`；
- `sourceIds` 写成**根源集合**（不是上一层），`transforms` 追加 `summarize`。

### 2.3 执行期闸门（闸2 闭包授权 + 闸3 污点/降级）

每次执行带 `sourceId` 的动作（摘要、打印、出站 docId）：

1. **闭包授权**：`prov.sources` 里每一个根源都必须在该令牌的 `documentIds` 内，
   否则 `闸2拒绝：来源未授权（M2,…）`——只看派生稿、不授权根源已经不行；
2. **污点闭包**：出站/打印动作若 `prov.tainted` → `闸3拒绝：内容来源受污染`
   （派生自被隔离的输入，即使摘要看起来正常也不放行）；
3. **等级单调**：`prov.maxLevel` 高于条目当前 `level` → `闸3拒绝：转换不得降级`。

拒绝都会写审计（含 `sources`），并计入风险计量。

## 4. 边界（必须如实写）

- 派生条目覆盖 read/summarize/OCR/转写/生成稿；**用户上传附件**已在 §6 按内容匹配补上，
  但只支持「整文件哈希 / 文本包含」两种匹配，二进制与短片段无法分析；
- `transforms` 目前是**显式工具名**，不是语义理解：没有“改名、复制、格式转换”这类工具，
  因此这些路径在本系统里不存在；不能宣称“理解任意转换”；
- 污点规则是 fail-closed：检出过注入的文档，其派生稿一律不能出站/打印，
  可能误伤“已人工确认安全”的场景——目前没有人工降级通道；
- 闭包不跨任务/跨 Agent：知识库按运行时会话累积，委托令牌不携带来源；
  多 Agent 协作下的来源传播是后续工作；
- 拒绝理由会出现在返回文案与审计里，但**不向模型暴露**来源细节（沿用原有错误反馈裁剪）。

## 5. 附件来源闭包（2026-11-17，同日第二刀）

用户上传的附件是裸字节、不带密级，是最容易绕过正文检查的通道。新增
`prototype/src/attachment-provenance.cjs`：

| 匹配方式 | 规则 |
|---|---|
| 整文件哈希 | `sha256(附件)` 等于某文档正文的哈希 → 强匹配 |
| 文本包含 | 附件按 UTF-8 解码后，包含某文档正文的前 48 字（短文档整段≥12 字）→ 匹配 |
| 二进制 | 含 NUL / 非法 UTF-8 / 不可打印比例高 → 不分析，标记「未分类」 |

命中后继承文档的**最高密级与污点**。策略（`checkAttachmentPolicy`）：

- 机密 → 一律拒绝；
- 污点 → 一律拒绝；
- 内部级 → **外部发送拒绝**（附件无法脱敏），内部邮件允许；
- 未分类 → 允许，但审计记录。

**两处执行**：

1. **冻结前**（`_checkAttachmentProvenance`）：直接抛出 409，附件不落 blob；
2. **发送前复核**（`_assertAttachmentsIntact`）：按当前知识库重新匹配，冻结后才读入的文档也能挡住。

审计新增 `附件来源检查`（含每个附件的 level/matched）与 `附件来源拒绝`。

测试 `prototype/test/attachment-provenance.test.cjs` 6 条：整文件匹配、文本夹带匹配、
二进制不误报、策略矩阵、冻结集成（机密/内部拒绝、普通放行）、发送前复核。

**边界**：不做语义理解；二进制附件不分析内容；少于 12 字的片段不匹配（可能漏检）；
匹配只与当前知识库/样例文档比对，外部来源的同内容文件（未入库）按未分类放行。
