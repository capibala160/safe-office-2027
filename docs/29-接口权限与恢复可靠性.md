# 接口权限、Cookie 容错、审计落盘状态（v0.29）

> 来源：对 v0.28 的复查。三个问题都成立，本轮修复并补测试。
> 本轮没有改评测语料，只补了续跑配置指纹。

## 1. 接口级角色权限（P1）

问题：角色约束只在命令入口；访客登录后仍能：

- 切换 `auto-full`
- 解除风险冻结（`/api/governance/review`）
- 对已有操作发起挑战、用虚拟设备批准并执行
- 重置工作区 / 回滚 / 导入资料

修复（`server.cjs`，启用登录时生效）：

| 能力 | 允许角色 |
|---|---|
| 发起确认 / 驳回 / 执行 / 校验操作 | 员工、管理员 |
| 虚拟设备批准 / 重放 | 设备助手、管理员 |
| 修改自动模式 / 重置 / 回滚 / 导入资料 / 审计篡改演示 | 管理员 |
| 风险复核 | 管理员、审计员 |
| 读取操作正文 / 历史 / 附件 | 员工、管理员、审计员 |
| 只读状态 / 列表 | 所有登录角色 |

- 未启用登录（本机演示）时保持旧行为；**一旦有用户表，接口级 403 生效**
- 新增 `allowVirtualConfirm`：启用真实动作（SMTP / 真实打印机）时默认关闭虚拟设备批准入口，
  返回 409，请改用手机/WS63 确认；`SAFE_OFFICE_ALLOW_VIRTUAL_CONFIRM=1` 可强制打开
- 关闭时：启动日志说明；`/api/bootstrap` 带 `virtualConfirm:false`，审批页显示可见提示

## 2. 坏 Cookie 不再打崩进程（P1）

- `parseCookie` 的 `decodeURIComponent` 加 try/catch，非法百分号编码返回 null
- 整个请求处理器外层加 `.catch`：未捕获异常统一 500 JSON，不再让 async rejection 退出进程
- 测试：`Cookie: sfc_session=%ZZ` → `/api/health` 200、`/api/bootstrap` 401、进程继续可用

## 3. 审计检查点父目录 + 落盘状态（P2）

- `_appendAudit` / `_saveAudit` 先 `mkdirSync(dirname(checkpoint), {recursive:true})`
- 新增 `auditPersist = {enabled, ok, error}`：
  - 落盘失败不再静默，`getState().audit.persisted=false` + `persistError`
  - 恢复失败单独暴露 `restoreError`
- 工作台审计卡：链有效但落盘失败会显示「链有效 · 落盘失败」，不再只显示“校验通过”

## 4. 评测续跑配置指纹（P2）

问题：`--resume` 复用旧样本时只按 tier/case 匹配，换模型、改提示词、换语料可能混入旧结果。

修复：

- 新增 `eval/fingerprint.cjs`：指纹覆盖 模型名 / llmKind / 语料版本 / split / tiers / repeats /
  消融层 / **PLAN_SYSTEM_PROMPT 哈希**
- 主跑分与消融续跑都要求 `prior.meta.fingerprint === 当前指纹`；不一致直接忽略旧样本并打印原因
- 旧 partial 没有 fingerprint → 一律不复用（安全默认）

## 5. 测试

- 新增：接口权限（访客 403 / 员工发起 / 设备批准 / 管理员模式）、虚拟入口 409、坏 Cookie 不崩溃、
  检查点父目录自动创建 + `persisted=true`、配置指纹 2 项
- 全仓 **303 项 Node 测试全绿**；浏览器 E2E 1 项通过

## 6. 边界

- 角色是**登录会话里绑定的**，没有租户隔离；所有用户共享同一个工作区
- 权限表是代码常量，不是可热更新的管理配置
- 访客仍可读状态/列表（不含操作正文/附件）
- 关闭虚拟批准后，本机若没有手机/WS63，就无法走高危确认——这是有意的 fail-closed
