# 登录 / 多用户（v0.25）

> 目标：控制台不再是“本机谁打开谁用”。加 **用户名+密码登录、HttpOnly 会话、角色绑定**；
> 多用户可以共用一套工作区。**租户隔离没做**（所有用户看到同一批操作/审计/资料），文档明确写清。

## 1. 用户与角色

- 用户表：`prototype/data/users.json`（已 gitignore，权限 0600）
- 密码：scrypt + 随机 salt；不存明文
- 角色：员工 / 实习生 / 审计员 / 设备助手 / 管理员 / 访客（与 Agent 角色表一致）
- 登录后角色**绑定在会话里**；命令请求里写别的角色 → 403，不能借 body 提权

添加/覆盖用户：

```bash
cd prototype
SAFE_OFFICE_NEW_USER_PASSWORD='至少8位' node add-user.cjs alice 员工
```

本机已生成两个初始账号，密码在 `prototype/data/initial-users.txt`（gitignore，0600）：
`alice`（员工）、`auditor`（审计员）。**登录后请改密码或删掉该文件**。

## 2. 会话

| 项 | 实现 |
|---|---|
| 登录 | `POST /api/login` → `Set-Cookie: sfc_session=...; HttpOnly; SameSite=Strict; Path=/` |
| 有效期 | 8 小时滑动过期；服务重启后会话失效（内存） |
| 登出 | `POST /api/logout` 清 Cookie + 删除会话 |
| 限流 | 登录 5 次/分钟/IP，超限 429 |
| 页面保护 | 未登录访问 `/` → 302 `/login.html`；API → 401 |
| 审计 | 每条命令写 `操作者` 事件（用户名 + runId），运行记录带 `operator` |

本机未启用登录（没有用户表）时保持旧行为：打开即用；`SAFE_OFFICE_AUTH=required` 可强制要求用户表存在。

## 3. 启动与配置

```bash
# 默认读 prototype/data/users.json；存在即启用登录
npm start

# 强制要求登录（没有用户表就拒绝启动）
SAFE_OFFICE_AUTH=required npm start
```

可选环境变量：

```bash
# SAFE_OFFICE_USERS_FILE=data/users.json
# SAFE_OFFICE_AUTH=required
```

## 5. 边界（重要）

- **不是租户隔离**：多用户共享同一批操作、审计、资料库与风险分；没有按用户分区。
- 会话在内存，重启后需重新登录；没有“记住我”持久会话。
- 没有改密码界面/找回密码；用 `add-user.cjs` 覆盖。
- 没有 2FA、没有 OAuth/LDAP；`Secure` Cookie 仅在 HTTPS 下自动加。
- 审计能记录“谁发起”，但操作记录本身没有 owner 字段（共享工作区）。
