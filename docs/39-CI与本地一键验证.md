# CI 与本地一键验证（v0.45 更新）

> 之前 346 项测试 + 7 项 E2E 全靠手跑，没有可复现的执行入口。
> 本轮补两样：**本地一键 `npm run ci`** + **可移植的 GitHub Actions 定义**。

## 1. 本地一键

```bash
cd prototype
npm run ci        # = lint && typecheck && typecheck:strict && npm test && E2E
```

- lint：语法 + 危险模式（`eval`/`new Function`）扫描，**不是完整 ESLint**。
- typecheck：`tsc -p tsconfig.json`（模块解析）；`typecheck:strict` 只对 `src/faults.cjs` 开启 checkJs。
- 单元/集成：`node --test --test-concurrency=1`（串行，避免测试文件并发起服务互相干扰）。
- 浏览器 E2E：`node --test e2e/ui.e2e.cjs`；优先用本机 Edge，没有则回退 Playwright 自带 Chromium。
- 任一步失败即非 0 退出，适合挂到任何调度器/脚本里。

单独跑也行：`npm test` / `npm run e2e`。

## 2. GitCode / GitHub CI 定义

仓库根目录有两份定义：

- `.github/workflows/ci.yml`：GitHub Actions（镜像到 GitHub 时生效）。
- `.gitcode/workflows/ci.yml`：**GitCode Actions（AtomGit 语法）**——`actions-repo/checkout@v4`、
  `actions-repo/setup-node@v4`、`runs-on: euler-latest`，不沿用 GitHub 的 `actions/*` 命名。

**当前状态（2026-11-03 实测）**：
- 仓库的「流水线 / Actions」入口未开通：访问 `/pipeline`、`/actions` 返回「页面找不到或无权限」，
  repo 页的流水线菜单为隐藏状态；
- 因此 **CI 没有在 GitCode 上跑过**，材料里不能写「GitCode CI 已通过」；
- **本地 `cd prototype && npm run ci` 是权威口径**，覆盖 lint + typecheck + 测试 + E2E。

开通入口后（仓库设置里启用流水线/Actions），`.gitcode/workflows/ci.yml` 会由 push / PR 触发；
若 runner 缺少 Playwright 系统依赖，E2E 可能失败，届时以本地结果为准。

## 3. 这条 CI 覆盖什么 / 不覆盖什么

**覆盖**

- 五道闸、策略与权限、令牌/委托、沙箱、审计链与检查点、租户隔离；
- 确认执行闭环（含 unknown 不重试）、退信 DSN、MCP 注册、日历 .ics；
- HTTP 接口权限、登录/2FA/改密、上传、退信、MCP、手机确认、虚拟设备确认（E2E）。

**不覆盖（环境依赖，故意跳过或 Mock）**

- ClamAV 真实扫描：未配置 `SAFE_OFFICE_CLAMAV_CMD` 时 1 项跳过（CI 无病毒库）；
- 真实 SMTP / 真实打印 / 系统日历：测试用 FakeMailer、模拟打印器、临时目录；
- 真实模型：评测 `eval/` 不进球型 CI（需要 key 与外部网络）；
- WS63 硬件：无串口/E2E 依赖虚拟设备。

这些项的验证方式见 `docs/35`（ClamAV 实测）、`docs/22`（SMTP 实测）、
`docs/38`（日历落盘）、`docs/21`（硬件四阶段）。

## 4. 边界

- 没有覆盖率统计；lint 不是完整 ESLint；`typecheck:strict` 只覆盖 `faults.cjs`——材料不能写「全量类型检查」。
- GitCode 流水线入口未开通；GitHub 定义未在远端跑过。**本地 `npm run ci` 是唯一权威口径**。
- 不自动发布/打包；CI 只证明"测试通过"，不产出可分发物。
- E2E 依赖浏览器二进制，首次运行需 `npx playwright install chromium`（本机已用 Edge 可跳过）。
