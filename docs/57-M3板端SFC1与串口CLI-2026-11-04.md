## 1. 板端固件（M3）

### 文件

| 文件 | 作用 |
|---|---|
| `ws63/firmware/board-confirm/board_confirm_m3.c` | 主任务：UART 收帧 → OLED 显示 → KEY2 决策 → 回 DECISION |
| `ws63/firmware/board-confirm/sfc1_hmac.c/h` | mbedTLS 3.6 HMAC-SHA256 + device_id 派生 |
| `ws63/protocol.c/h` | 帧编解码/校验（与 PC 测试共用同一份源码） |
| `ws63/firmware/build-m3.cjs` | 同步进 SDK + 清理旧对象 + 调 `build.py` |

### 行为

- UART0，**115200 8N1**，与控制台共用；PC 侧解析器按 `SFC1` 魔数重同步，文本日志不干扰
- 收到 CHALLENGE：验 MAC → 查重放窗口 → 检查是否有未过期待确认 → 存 pending 并显示
- OLED：`WS63 CONFIRM` / 动作（SEND EXT / DELETE / PRINT / DEVICE）/ 摘要 / `OK:SHORT NO:LONG <TTL>s`
- KEY2 短按 = 批准（decision=1），长按 ≥600ms = 取消（decision=0）；与 M2 相同的候选脚+去抖
- 回 DECISION：HMAC-SHA256，`device_id` 与 PC 同域派生，`decided_at` 用本地毫秒时钟
- 超时：按 `expires_at - issued_at` 换算本地 deadline（板上无 RTC），到点清 pending 并消费 nonce
- 重放：8 条 nonce 环形窗口；过期 pending 的 nonce 也会被消费

### 固定值（演示）

- PSK：`DEMO_KEY` = 32 × `0x42`（与 CLI `--demo-key` 对应）
- 设备名：`ws63-A`；`device_id = SHA-256("safe-office/ws63/device-id/v1\0" + "ws63-A")[0..8]`
- ⚠️ 真实部署必须改为每台设备独立密钥 + 安全存储；当前仅用于联调

### 编译

```bash
node ws63/firmware/build-m3.cjs            # 只同步源码进 SDK
node ws63/firmware/build-m3.cjs --build    # 同步 + 编译（约 18s，增量）
# 或在 prototype/ 下：npm run ws63:build
```

产物：`D:/fbb_ws63/src/output/ws63/fwpkg/ws63-liteos-app/ws63-liteos-app_all.fwpkg`

## 2. PC 侧串口确认 CLI

```bash
cd prototype
node serial-confirm.cjs --port COM12 --demo-key --to partner@example.com --subject "Quarterly report"
node serial-confirm.cjs --port COM12 --key <64位hex> --device ws63-A --action printDoc --to "HP LaserJet"
```

| 选项 | 说明 |
|---|---|
| `--port` | 必填，CH340 的 COM 号（以设备管理器为准，可能变） |
| `--to` / `--subject` / `--body` | 操作内容；摘要进 CHALLENGE，OLED 显示 |
| `--action` | `sendExternalEmail`(1) / `deleteDoc`(2) / `printDoc`(3) / `deviceControl`(4) |
| `--device` | 期望设备名，默认 `ws63-A` |
| `--ttl` / `--timeout` | 确认 TTL（默认 30s）/ 串口回复超时（默认 15s） |
| `--demo-key` | 使用演示密钥（必须显式） |
| `--key` / `SAFE_OFFICE_SFC1_KEY` | 真实 32 字节密钥（64 位十六进制） |
| `--json` | 机器可读输出 |

退出码：`0` 批准；`2` 取消；`1` 其它失败（TIMEOUT/MAC/DEVICE/DECISION…）。

流程与虚拟设备完全一致：`sealOperation` 冻结 → `NearfieldConfirmer.beginChallenge` →
`SerialTransport.send` → 板端按键 → `acceptDecision` 验 MAC/绑定/nonce。

## 3. 测试

新增 `prototype/test/serial-confirm.test.cjs` 6 项（假串口 + 真 SFC1 帧 + 真 HMAC）：

- 正常批准：CHALLENGE 真的写到串口，返回 decision=1，结束后关闭串口
- 板端取消 → `DECISION`（cancelled=true）
- 板端无响应 → `TIMEOUT`
- 应答被篡改 → `MAC`
- 设备 ID 不匹配 → `DEVICE`
- `buildOperation` 动作白名单 / 必需收件人

## 4. 边界

- **固件未上机验证**：编译通过 ≠ 真机通过；UART0 与控制台共用、RX 回调注册、OLED 显示、
  mbedTLS 链接都只经过编译验证
- 演示 PSK 编译进镜像；无安全存储、无密钥轮换
- 板上无 RTC：TTL 用本地时钟换算，设备重启后 pending 丢失（重启后旧挑战不能复用，nonce 窗口也清空——
  这是已知边界，真机验收时要单独测"确认中拔电"）
- OLED 字体不含中文：摘要含中文会显示 `?`；演示建议用 ASCII 主题
- 不证明距离/身份/防中继
