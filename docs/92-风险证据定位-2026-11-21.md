# 风险证据定位：命中原文与已移除动作（v0.54.2，2026-11-21）

> 目的：让“为什么被拦”不再只有一句话术标签，而是可核对的两类证据：
> **① 命中的原文片段**（在隔离原文中高亮定位）；**② 被计划校验移除的动作**（动作名 + 原因）。
> 证据只记录**哈希 + 偏移量**，不在审计里复制注入原文。

## 1. 后端

### 1.1 闸1 记录命中区间

`sanitizeInput(text)` 按句切分（`。！？\n`）时维护字符偏移，命中注入模式的句子记录
`{ start, end }`，最多 20 段：

```js
{ safe, reasons, cleaned, ranges: [{ start, end }] }
```

- 偏移量对**原始文档**（`knowledge.body`）计算，不是对清洗后的文本；
- 只记位置，不把命中句子写进审计；
- 同一句命中多个模式时，理由仍全部收集。

### 1.2 审计与运行结果

`runtime` 的「闸1触发」审计新增：

```js
documentHash: sha256Hex(doc.body), ranges
```

`ConsoleService` 运行结果新增 `riskEvidence`（最多 20 条）：

| type | 含义 | 字段 |
|---|---|---|
| `source` | 被隔离的资料 | `docId` / `documentHash` / `ranges` / `reason` |
| `removed` | 计划校验移除的动作 | `action` / `reason` |

同时「闸1触发」纳入执行结果的警告阶段（`gateSummary`），不再只藏在审计明细里。

### 1.3 文档接口

`GET /api/documents/:id` 新增 `documentHash`（对 `originalBody` 计算），
用于前端核对“这条区间记录是否仍对应当前文档版本”。

## 2. 前端

- 执行结果右侧「当前待办」下方新增**风险证据**列表：
  - 资料类：`已隔离资料 M3` + 理由 +「查看命中原文」按钮；
  - 动作类：`已移除动作 · 对外发邮件` + 原因。
- 点击「查看命中原文」：
  - 重新按授权读取文档；
  - 校验 `documentHash` 与当前 `originalBody` 一致后，用 `ranges` 切段并渲染
    `<mark class="risk-match">` 高亮；
  - 自动展开「查看原始资料」，聚焦并滚动到第一个命中；
  - 哈希不一致时显示「这条记录缺少与当前文档版本匹配的原文定位」，不猜测位置。
- 被移除动作只展示工具名与原因，不提供“确认/继续”入口。

## 3. 验证

- 新增 E2E：**「风险说明可定位到隔离原文并展示移除的动作」**
  - 运行 `injection` 样例 → 出现「已移除动作 · 对外发邮件」；
  - 点「查看命中原文」→ `mark.risk-match` 出现，文本含「忽略以上所有指令」，且获得焦点；
  - 不出现确认按钮。
- 服务层断言：`riskEvidence` 中 M3 的 `documentHash` 与文档一致，所有区间
  `end > start && end <= originalBody.length`；存在 `removed sendExternalEmail`。
- `npm run ci` 全绿：**646 通过 + 2 跳过、E2E 18/18**、lint/typecheck/strict 全过。

## 4. 边界

- 只支持**文本/转写文本**的句子级定位；图片 OCR 的命中暂不提供坐标高亮。
- 最多 20 段；超出的命中仍会隔离，但不再追加区间。
- 审计只存哈希 + 偏移，不存原文；查看原文仍走文档接口的授权/租户/共享校验。
- 文档内容变化后，旧区间记录会因哈希不匹配而**主动放弃高亮**，不会错标到新正文。
- `ranges` 依赖 `sanitizeInput` 的切句规则；若切句规则变化，旧记录可能无法匹配，此时按哈希不一致处理。
