# 手机确认端（v0.14）

> 2026-10-22 建立。用途：锦创杯黑客松不用 WS63 板时，把"就近的人一秒钟授权"演出来。
> 与主线的关系：复用 SFC1 协议与冻结操作闭环，**不改协议、不新增状态机**；只把"谁签 DECISION"从上位机的虚拟设备换成手机。

> **v0.23 更新（2026-10-30）**：补上配对会话与限流。此前 `--lan` 下任何局域网设备都能
> `GET /api/phone/state` 读到待确认操作的收件人/正文预览，也能无限次尝试提交。
> 现在：
> - `POST /api/phone/pair` 用配对码换 **10 分钟滑动会话 token**（常数时间比较）；
> - `state` / `decision` 必须带 `X-Phone-Session`，否则 401；
> - 配对失败 **5 次/分钟/IP**、确认提交 **10 次/分钟/IP**，超限 429；
> - 确认页把 token 存本地，401 自动回到配对页。
>
> **边界不变**：仍是 PSK 对称密钥；“持有配对码 + 会话”只证明设备端参与了确认，
> 不构成“证明本人在场”，也没有多用户身份。

## 1. 为什么是手机，不是键盘

键盘版（`npm run demo:nearfield`）能演流程，但"就近的人持有设备"只能靠嘴说。手机是真实终端：
- 页面在**端上**解 CHALLENGE、验 MAC、组 DECISION 帧并签名；
- 服务器只转发帧，不代签；
- 审计里能看到设备 ID、nonce、确认时刻。

**边界（必须照实说）**：SFC1 是 HMAC 对称密钥，验证端也持同一把 PSK，所以这套东西证明的是"确认动作发生在端上、且留了痕"，**不证明持机人在物理现场**；防中继/防代持仍不成立。

## 2. 运行

```bash
cd prototype
npm run start:lan          # 等价于 node server.cjs --lan
```

终端会打印：
- 配对码（`--code=XXXX-XXXX` 可固定，或环境变量 `SAFE_OFFICE_PHONE_CODE`）
- 若干条 `http://<局域网IP>:7812/confirm.html  (<网卡名>)`

手机连同一个 Wi-Fi，打开对应地址，输入配对码 → 进入待命。
控制台仍只在本机 `http://127.0.0.1:7812` 使用。

## 3. 端上做了什么

| 步骤 | 位置 | 说明 |
|---|---|---|
| 配对 | 手机页面 | 配对码 → HKDF-SHA256 → 32B PSK；码不上传 |
| 收挑战 | 手机轮询 `/api/phone/state` | 拿到 SFC1 CHALLENGE 原始帧（base64） |
| 验帧 | 手机 | `decodeFrame`：magic/版本/长度/类型/**MAC**/生命周期；**显示的是帧里的摘要，不是服务器给的字段** |
| 签名 | 手机 | `encodeDecision`：taskId/nonce/decision/deviceId/decidedAt + HMAC-SHA256 |
| 回传 | 手机 → `POST /api/phone/decision` | 服务端用同一 `acceptDecision` 校验并推进冻结操作 |

端上实现 `public/sfc1-browser.js` 与 `src/ws63-protocol.cjs` **字节级一致**（`test/sfc1-browser.test.cjs` 有 parity 断言）。

### 为什么带纯 JS 兜底
`crypto.subtle` 只在 https/localhost 可用；手机通过 `http://192.168.x.x` 打开时是**非安全上下文**，没有 WebCrypto。
所以页面在无 WebCrypto 时改用内置 SHA-256/HMAC/HKDF（已与 Node 逐项对拍）。
**这是演示用实现**：非恒时，不能当生产密码学用；生产应走 https + WebCrypto 或硬件密钥。

## 4. 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/phone/state` | 当前待确认挑战（原始帧 + 摘要 + 剩余秒）+ 上次结果 |
| POST | `/api/phone/decision` | `{ challengeId, frame }`，frame 为 base64 的 SFC1 DECISION |
| GET | `/api/device` | 控制台用：设备信息 + 配对码（仅回环地址可取） |

局域网来源（非回环）**只放行** `/confirm.html`、`/confirm.css`、`/confirm.js`、`/sfc1-browser.js`、`/api/phone/state`、`/api/phone/decision`、`/api/health`；其余一律 403。这样会场 Wi-Fi 上不会暴露整个控制台。

## 5. 演示脚本（4 个动作）

1. **正常**：命令台发外发 → 生成冻结操作 → 点"发起确认" → 手机亮起 → 点"确认执行" → 操作 `executed`，邮件 `sent`。
2. **超时**：手机不按，等 30 秒（或控制台点"模拟超时"）→ `EXPIRED`，nonce 消费，操作仍 `frozen`。
3. **取消**：手机**按住 0.6 秒**取消 → `DECISION`，操作转 `rejected`，留痕。
4. **错设备**：第二台手机打开 `confirm.html?device=phone-B`，同一配对码 → 服务端回 `DEVICE`（设备 ID 不匹配），操作仍 `frozen`。

可选：**篡改**——手机侧把帧改一个字节再提交，`MAC` 拒绝；控制台"篡改"按钮同理。

- `test/sfc1-browser.test.cjs`（10 项）：帧字节一致、端上解帧/验签、错密钥与篡改拒绝、device/task 派生一致、HKDF 与纯 JS 兜底对拍

- 无头 Edge 真机路径冒烟：以**局域网 IP**打开（非安全上下文 → JS 兜底），配对 → 收挑战 → 验签 → 批准 → 操作 `executed`

全套 **199 项 Node 测试**通过。

## 7. 未做 / 边界

- 没有 https（配对码与帧在局域网内明文传输；帧有 MAC，配对码没有）
- 配对码可被同网段的人看到（控制台屏幕/终端），配对后无法远程吊销
- 单设备密钥；多确认端、密钥轮换未做
- 页面轮询 1 秒，不是推送；断网后重连靠下一轮
- 不提供距离/身份/防中继证明
