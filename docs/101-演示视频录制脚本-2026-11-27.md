## 1. 角色、窗口与设备

| 角色 | 账号 | 用途 |
|---|---|---|
| 员工 | `demo` | 跑任务、冻结外发、改收件人/附件、看回放 |
| 设备助手 | `helper` | 设备页点「确认」把挑战帧下发到 B 板，等待物理按键 |

- 密码在 `prototype/data/initial-users.txt`，只在本机看，**不要出现在画面里**。
- 四眼原则：`demo` 发起的操作不能由 `demo` 自己批准，必须用 `helper`。
- B 板 = 确认板（`SAFE_OFFICE_DEVICE=ws63-B`）；A 板 = 执行板（`SAFE_OFFICE_ACTUATOR_DEVICE=ws63-A`）。
- 同屏镜头：显示器 + B 板 OLED 在一个画面里；手机/相机用三脚架固定，先对焦 OLED。

## 2. 录制前检查（建议提前 30 分钟）

### 2.1 插板与识别端口

1. 两块板都插 USB（数据线，不是只供电线），确认设备管理器出现两个 `USB-SERIAL CH340`。
2. 逐块识别身份（每次插拔后都要重做）：

```bash
cd prototype
node scripts/ping-device.cjs --port COM11 --device ws63-B
node scripts/ping-device.cjs --port COM12 --device ws63-A
```

把实际端口记下来；如果返回失败，换端口再试，**不要凭上次的 COM 号猜**。

3. 关闭所有占用串口的程序：HiSpark Studio 串口监视、PuTTY、其他 `npm start`、`serial-cli`。同一串口只能被一个进程打开。

### 2.2 修正端口配置

当前 `prototype/config.env` 里 `NEARFIELD_PORT` 与 `ACTUATOR_PORT` 都写着 `COM11`。如果两块板都插：

- `SAFE_OFFICE_NEARFIELD_PORT` = B 板实际端口（确认）
- `SAFE_OFFICE_ACTUATOR_PORT` = A 板实际端口（执行）
- 两个值必须不同，否则执行动作会抢同一个串口。

如果视频不拍门锁动作，只插 B 板也可以；此时不要执行「设备控制」样例。

### 2.3 启动服务（录制用：强制模拟邮件）

本机 `config.env` 配了真实 QQ SMTP。录制外发时如果走真实 SMTP，会真的尝试发信、结果不可控。用下面的命令启动，空环境变量优先于配置文件，强制 FakeMailer：

```bash
cd prototype
SAFE_OFFICE_SMTP_HOST= SAFE_OFFICE_SMTP_ACCOUNTS= SAFE_OFFICE_SMTP_USER= \
SAFE_OFFICE_SMTP_PASS= SAFE_OFFICE_IMAP_HOST= npm start
```

启动日志应出现：

- `执行端：ws63-A @ COMxx / IO12 继电器`
- 确认端使用 `ws63-B`、串口为 B 板实际端口
- 邮件为模拟发送（无 SMTP 账号）

### 2.4 模型选择（二选一，先拍板）

| 方案 | 启动方式 | 优点 | 风险 |
|---|---|---|---|
| **A. 规则化演示（推荐）** | 再加 `SAFE_OFFICE_LLM_ENDPOINT= SAFE_OFFICE_LLM_KEY= SAFE_OFFICE_LLM_MODEL=` | 注入样例结果确定，不用等模型 | 顶栏显示「本地 Mock」，需避开顶栏或字幕注明「演示模式」 |
| B. 真实模型 | 保持 config.env 的 DeepSeek | 顶栏显示真实模型 | 规划可能 10–60 秒、结果有波动，需重录 |

推荐 A 拍攻击样例（结果可控），报告里的真实模型数字用字幕/口播单独说明；如果评委更看重「真模型」，再用 B 补拍一个正常任务镜头。**不要混剪成“实时真实模型”却不说明。**

### 2.5 准备附件与窗口

1. 桌面准备两个文件，**同名同大小、内容不同**：
   - `agenda.txt`：`Agenda: initial draft`（21B）
   - `agenda.txt`：`Agenda: updated draft`（21B）
2. 浏览器开两个窗口：`demo`（员工）与 `helper`（设备助手）；缩放 110%，隐藏书签栏。
3. 预先打开页面：工作台、命令台、设备、回放。
4. 关闭微信/QQ/系统通知，开启专注助手；录屏软件只录浏览器窗口，避免露出其他资料。
5. 试录 10 秒：确认麦克风、OLED 字迹、网页小字都能看清。

## 5. 按键口径与重录点

| 项 | 口径 |
|---|---|
| 批准 | 短按 KEY2，<600ms；**轻点立即松手** |
| 取消 | 长按 KEY2，≥600ms |
| 等待 | OLED 摘要出现后停 2 秒再按，给镜头对焦时间 |
| 旧挑战 | 先让助手点「确认」把旧帧发到板上，再改网页内容，最后按旧键 |
| 新挑战 | 旧挑战作废后重新发起；一个时间只允许一个 pending |
| TTL | 挑战 90 秒；助手点「确认」后串口等待约 65 秒，改动要在窗口内完成 |
| 误长按 | 板端会回取消；本段重录，不要剪成“批准” |

**常见失败**：

1. 板子没插/端口变了 → 重跑 `ping-device`，改 config.env，重启服务。
2. 串口被占用 → 关掉串口监视/旧服务，必要时拔插 USB。
3. 助手页没有新挑战 → 设备页不会自动刷新，点一次「设备」导航或刷新页面。
4. 板端显示旧摘要但 PC 报超时 → 按键太晚（>65 秒）或帧没下发；重做本段。
5. 执行显示失败 → 检查是否误走了真实 SMTP；确认启动命令里的空环境变量生效。
6. 误触「发起挑战」而非「确认」→ 设备页的「发起挑战」只创建挑战，真正下发是 OLED 面板里的「确认」。
