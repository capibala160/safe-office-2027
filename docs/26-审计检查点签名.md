# 审计检查点签名 + 独立路径（v0.26）

> 问题：审计 JSONL + 同目录 `audit.head` 只能发现“链被改”，挡不住**有写权限的人把链和检查点一起换掉**。
> 这一轮把检查点做成 **HMAC-SHA256 签名**，并允许放到**独立路径/另一块盘**。

## 1. 机制

- `AuditLog.signCheckpoint(checkpoint, key)` → `{count, head, alg:'HMAC-SHA256', mac}`
- 恢复时：
  1. 检查点有 `alg` 但没有 `SAFE_OFFICE_AUDIT_KEY` → 拒绝恢复；
  2. 配了 key 但签名不匹配 → 拒绝恢复（从新链开始并记「审计恢复失败」）；
  3. 旧的无签名检查点 + 配了 key → 同样拒绝（需先清理旧审计或临时不配 key 迁移）。
- mac 覆盖 `{count, head}`；改任意一个都会失效。

## 2. 配置

```bash
# 32 字节 base64（或 64 位 hex）；丢失将无法验证/恢复已签名审计链
SAFE_OFFICE_AUDIT_KEY=...

# 可放到另一块盘/受保护目录；默认 audit.jsonl.head
SAFE_OFFICE_AUDIT_CHECKPOINT=D:/secure/audit.head
```

本机 `prototype/config.env` 已生成 key；检查点默认仍在 `prototype/data/`，要真正跨盘请改 `SAFE_OFFICE_AUDIT_CHECKPOINT`。

生成 key：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

## 4. 边界

- 防的是**只有磁盘写权限**的攻击者；进程/环境变量被控制时仍可伪造。
- 检查点文件本身可被删除 → 恢复拒绝并开新链（不会静默接受旧链）。
- 没有外部时间戳/透明日志（如 Rekor）；不能证明“某时刻之后没发生”。
- 密钥丢失 = 已签名审计链无法再验证；需要备份 key。
