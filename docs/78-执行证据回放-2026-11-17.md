# 执行证据回放（2026-11-17）

> 把一次运行的「用户要求 → 计划/批准 → 闸与风险 → 实际调用 → 回执」拼成一条可核对的时间线，
> 并给出证据完整性结论。只读视图，不补造数据。
>
> 结论：`GET /api/runs/:runId/replay` 可用；4 条测试；全量 **629（627 通过 + 2 跳过）**、
> lint/strict 全绿。**控制台前端页面尚未做**（只有 API + 文本渲染）。

## 1. 数据来源（都是已有记录）

| 段 | 来源 |
|---|---|
| 要求 | 控制台 `runs[].command/role/tools/documentIds/risk`（运行结束即落内存，最多 50 条） |
| 计划 | 操作的 `planHash`/`modelId`（不保存原始计划文本） |
| 闸/风险 | 该 run 的审计切片（`runs[].audit.from/to`），筛 闸1/闸2/闸3/闸5/策略/沙箱/计划校验/待确认/附件来源/来源闭包 等 |
| 批准 | 操作记录的 `operationHash/confirmationId/deviceId/state/expiresAt` |
| 实际调用 | 审计 `执行` 条目（步骤号/动作/结果） |
| 回执 | `outbox`（state/messageId/lastError/note） |
| 完整性 | run 的审计链校验结果 + 逐条 `verifyOperation`（重算 operationHash） |

## 2. 输出结构

`buildTaskReplay()`（`prototype/src/task-replay.cjs`）返回：

```js
{ runId, at, command, role, operator, tools, documents, risk,
  gates: [{seq, at, kind, detail}],
  calls: [{seq, at, n, action, outcome}],
  approvals: [{operationId, action, recipient, level, state, operationHash,
               confirmationId, deviceId, planHash, modelId, receipt}],
  integrity: { auditVerified, auditRange, operations: [{operationId, ok, reason}] },
  warnings: [] }
```

`renderTaskReplay()` 输出纯文本时间线（便于 CLI/答辩打印）。

**警告规则**：

- 审计链校验失败 → 警告；
- 任一操作 `verifyOperation` 失败（正文/附件/收件人被改）→ 警告；
- 回执 `unknown`（发送结果未知）→ 警告「禁止自动重试，需人工核对」。

**不臆造**：没有操作就显示「没有执行记录」；没有回执就显示「(未发送)」；
`sent` 只代表服务端已发出，**不代表对方已读**。

## 3. 接入

- `ConsoleService.getTaskReplay(runId, { actor, role })`：按运行可见性控制（他人运行 404）；
- HTTP：`GET /api/runs/:runId/replay`，需要操作读取权限（`ROLE_OP_READ`）；
- 只对**已完成的运行**提供；运行中返回 404 语义（证据尚未形成）。

## 4. 验证

`prototype/test/task-replay.test.cjs` 4 条：

1. 要求/闸事件/批准/调用/回执串联，完整性为真；
2. `unknown` 回执 + `verifyOperation` 失败 → 两条警告；
3. 审计链未通过 → 明确警告；
4. 控制台集成：真实运行后按 `runId` 取回放；未知 runId 404。

全量 **629（627 通过 + 2 跳过）**；lint、strict 全绿。

## 5. 边界与未做

- **前端回放页面未做**：目前只有 API 与文本渲染，答辩演示需要页面时再补；
- 计划阶段只存 `planHash`/`modelId`，**没有原始计划文本**，回放不能逐字重放模型输出；
- 板端确认帧不落库（只有 `confirmationId/deviceId`），不能回放原始 SCEP 字节；
- 回执不等于送达：`sent` 是 SMTP 接受，退信另见退信记录；
- 运行记录只保留最近 50 次（内存/落盘状态），更早的要靠审计归档；
- 审计切片依赖 `runs[].audit.from/to`；进程重启后运行记录来自 `console_state`，切片仍按原序号。

## 6. 后续

1. 控制台「任务回放」页面（时间线 + 完整性徽标 + 一键导出）；
2. 回放里展示委托链（父/子令牌）与来源 `transforms`；
3. 归档任务：从审计归档重建更早的回放。
