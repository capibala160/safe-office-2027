## 1. P1 租户审计误报「校验通过」

**问题**：`getTenantAudit` 用当前内容重新生成检查点，再拿它和自己比较，篡改后仍报 `verified:true`。

**修复**：

- 新增独立落盘的租户检查点 `audit.tenants`（HMAC 签名，`SAFE_OFFICE_AUDIT_KEY`）。
- `getTenantAudit` 先验全局链 `audit.verify()`，再与**独立保存的可信检查点**做前缀比对；无检查点/签名无效/不一致一律 `verified:false`，并返回 `reason`。
- `verifyTenant` 改为前缀校验：检查点可以落后于当前链（之后追加的新条目不会把旧检查点判成篡改），但前缀内任何改动都会失败。
- 治理页 `audit.tenants` 返回 `trusted / checkpointCount / verified`。

**测试**：`test/audit-tenant.test.cjs` 新增「无检查点不报通过」「篡改后全局/租户都失败」「前缀追加不误报」。

## 2. P1 部署模板没有强制登录

**问题**：全新部署没有 `users.json` 时跳过角色校验；接入 HTTPS 反代后可能匿名操作。

**修复**：

- `docker-compose.yml` 设置 `SAFE_OFFICE_AUTH=required`；没有用户表时容器拒绝启动（fail-closed）。
- `deploy/README.md` 增加首次管理员创建步骤（`add-user.cjs`）。
- 端口只映射 `127.0.0.1`；`SAFE_OFFICE_TRUST_PROXY=1` 仅在可信反代后开启。

## 3. P2 多发件账号没有贯通审批流程

**问题**：`sealOperation()` 丢弃 `mailAccount`，改字段也不影响 `operationHash`。

**修复**：

- `operation.cjs`：`mailAccount` 进入规范化哈希（空值不写入，兼容旧记录）。
- `store.cjs`：`operations` 表新增 `mail_account` 列（旧库自动补列），插入/读取贯通。
- `console-service.cjs`：命令入参校验账号（只允许字母/数字/._-；配置了账号池时必须是已知账号），冻结、编辑重签、审批视图、SQLite 全链路保留。
- `views.js`：操作卡片显示「发件账号」。

**测试**：`fulfillment.test.cjs`（哈希变化/篡改断链/落库读回）、`console-service.test.cjs`（命令→冻结→SQLite→哈希）。

## 4. P2 真实邮件预览缺少 MIME 解码

**问题**：Base64 邮件显示编码字符串；multipart 可能显示边界和附件编码。

**修复**：

- 先读 `bodyStructure`，优先选 `text/plain`，没有则 `text/html`。
- 支持 `base64`、`quoted-printable`、`7bit/8bit`；按 `charset` 用 `TextDecoder` 解码，失败回退 UTF-8。
- HTML 去标签后截断 200 字。

**测试**：`imap-inbox.test.cjs` 新增 base64 / quoted-printable / HTML / 字符集 / multipart 选择。

## 5. P2 预览会下载整封原始邮件（含附件）

**修复**：

- 只 `download` 选中的文本段，`readLimited` 上限 **256KB**；不再 `fetchOne({source:true})`。
- 整体读取加超时（`2 × timeoutMs`）；同一时刻只允许一个读取（`_inflight` 去重）；结果缓存 30 秒。
- 无文本段/服务器不支持按段下载时，只返回元数据与 `previewError`，不退回下载整封。

**测试**：`imap-inbox.test.cjs` 断言 `fetchOne` 不请求 `source`、`download` 只取 `part`、不调用 `messageFlagsAdd`。

## 6. P3 健康检查成本 / 类型检查

- `/api/health` 改走 `service.health()` 轻量探针，不再调用 `getState()` 统计全量操作/文档/审计；保留版本、启动时间、uptime。
- 新增 `typecheck:strict`：先对 `src/faults.cjs` 开启 `checkJs`；其余核心模块逐步纳入。
- 修复测试偶发 `bad port`：`startServer` 在 `port:0` 分配到 fetch 禁用端口时自动关闭重试。
