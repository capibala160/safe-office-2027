# 屏幕共享真实化（v0.50，2026-11-04）

> 目标：把 `shareScreen` 从「返回一句已开启」变成**真实投屏 + 可审计**。
> 画面只在浏览器本地采集与预览，**不上传服务器**；服务端只记录「谁、何时、共享到哪、持续多久」。

## 1. 链路

```
控制台（浏览器）
  getDisplayMedia() ──> 本地 <video> 预览（画面不离开本机）
        │
        └─ POST /api/screenshare/start ──> 审计「屏幕共享开始」{target, surface, sessionId}
        └─ POST /api/screenshare/stop  ──> 审计「屏幕共享结束」{durationMs, ...}
```

## 2. 接口

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| POST | `/api/screenshare/start` | `{target, surface}` | `{sessionId, target, surface, startedAt}` |
| POST | `/api/screenshare/stop` | `{sessionId}` | `{target, surface, durationMs}` |

- 权限：登录用户（`ROLE_STAFF`）；审计身份走请求级 AsyncLocalStorage，并发不串号。
- 校验：目标必填且 ≤64 字；`surface` 只接受 `monitor/window/browser/unknown`，其余归一为 `unknown`。
- 未知会话返回 404；开始/结束都写审计链。

## 3. 运行时与能力表

- `runtime.cjs` 的 `shareScreen` 效果改为「屏幕共享已下发：目标 X —— 请在控制台『设备 → 屏幕共享』点选窗口，服务端记录开始/结束（画面不上传）」。
- `capabilities.cjs` 的约束/描述同步：投屏由控制台 `getDisplayMedia` 真实发起，服务端只记审计。
- **闸与策略不变**：知识库存在机密材料时仍禁止共享（防连带泄露）。

## 4. UI

设备页新增「屏幕共享」卡片：

- 目标输入（默认「会议室大屏」）、开始/停止按钮、`<video>` 本地预览、状态徽章。
- 用户从浏览器条停止共享、或离开页面时，自动停采集并写结束审计。
- **限制**：`getDisplayMedia` 只在安全上下文可用（localhost 或 HTTPS）；用局域网 IP + HTTP 打开控制台时按钮会提示不支持。

## 5. 边界（必须写进材料）

- 只证明「本机浏览器采集了某个 surface」；**不证明远端看到、不证明参会人收到**。
- 服务端不接触画面内容，无法验证共享的是哪个窗口（`displaySurface` 由浏览器上报）。
- 不支持多端分发 / WebRTC / 录屏。
- 共享目标只是审计标签，不参与权限判断。

## 6. 验收

- 单测：开始/结束写审计、时长按 `now` 计算、缺目标被拒、非法 surface 归一、未知会话 404。
- HTTP：`/api/screenshare/start` → 200、`stop` → 200、未知会话 → 404。
- E2E：设备页渲染共享卡片（默认目标、停止按钮初始禁用）。
- `npm test` **556 项（554 通过 + 2 跳过）**，`npm run e2e` **11/11** 全绿。
- ⚠️ **未做**：真实点击「开始共享」的系统选屏窗口（自动化拿不到 getDisplayMedia 权限），需人工在 localhost 控制台点一次确认。
