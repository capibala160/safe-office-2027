> **strict 扩到安全核心/持久化 + 3 条新 E2E**。
> 验证：**463 项 Node 测试（461 通过 + 2 跳过）**、**11 项浏览器 E2E**、lint / typecheck / typecheck:strict 全过。

## 1. 演示前自检

### CLI

```bash
npm run demo:preflight
npm run demo:preflight -- --json
npm run demo:preflight -- --data-dir="data/demo" --port=7812
```

- 退出码：`0` = 无阻塞项；`1` = 有 `fail`
- 检查项：Node 版本、数据目录可写、登录账号、审计落盘/检查点、Ed25519 签名、外部快照目录、
  模型（真实/Mock）、SMTP/IMAP、日历、打印、ClamAV、Edge、一键演示包、控制台端口
- 状态三档：`ok`（可用）、`warn`（可演示但有边界）、`fail`（直接影响演示）

### HTTP + 工作台

- `GET /api/preflight`（仅管理员）返回同一套检查项；工作台新增「演示前自检」卡片，可点「重新检查」
- 只读：不启动服务、不写数据、不主动访问外网；端口探测只连 `127.0.0.1`

### 边界

- 自检不验证真实 SMTP/IMAP 登录，也不实际调用模型；只确认配置存在
- 控制台端口占用只提示，不自动杀进程

## 2. 全量数据备份/恢复

### 备份

```bash
npm run backup
npm run backup -- --out=D:/backup/safe-office
npm run backup -- --include-demo --json
```

- 默认备份 `prototype/data/` 下的：操作库、文档库、附件库、审计链/检查点/租户检查点、
  `audit-archive/`、`keys/`、`calendar/`、`print/`
- **默认排除**：`initial-users.txt`（明文初始密码）、`config.env`（含密钥）、`demo/`（加 `--include-demo` 才备份）、符号链接
- 输出目录含 `manifest.json`（相对路径、大小、sha256、排除项），manifest 最后原子写入
- 默认输出到 `prototype/backups/backup-<时间>/`（已 gitignore）

### 恢复

```bash
npm run restore -- --from="D:/backup/safe-office/backup-..." --force
```

- 先校验 manifest：缺失、大小、哈希、路径越界都会拒绝
- 默认拒绝覆盖；`--force` 时先把现有文件改名为 `*.pre-restore-<时间>` 留档，再复制
- 服务仍在运行时（端口 7812 占用）默认拒绝；`--force` 可跳过探测，但 SQLite 可能仍被占用

### 边界

- **备份本身不加密**：请放在受控目录/加密盘；备份包含用户密码哈希与审计链
- **建议先停服务**：运行中的 SQLite WAL 可能处于中间态；CLI 不做在线一致性快照
- 恢复不校验业务语义，只保证文件与备份时一致

## 3. 审计快照定时导出 + 保留

```bash
SAFE_OFFICE_AUDIT_EXTERNAL_DIR=E:/audit-offsite
SAFE_OFFICE_AUDIT_EXPORT_INTERVAL_MIN=30   # 0 = 关闭（默认）
SAFE_OFFICE_AUDIT_EXPORT_KEEP=7            # 保留最近 N 份
```

- 启动后按间隔调用现有 `exportAuditSnapshot`，再调用 `pruneAuditSnapshots` 删除超出保留份数的旧快照
- 只处理外部目录下的 `snapshot-*` 目录；删除前做路径包含校验
- 失败写入 `auditExportState.lastError`，不抛出、不阻塞服务；治理页显示定时间隔/保留份数/上次结果
- 关闭服务时 `stopAuditExportTimer()` 清理定时器

### 边界

- 仍是**本地文件复制**，不是对象存储；快照清单只证明副本与导出时一致
- 定时导出本身会追加审计；导出失败不会自动重试，下一轮再试
- 没有分布式锁：同一外部目录被多个实例同时写入时，快照名可能冲突（单实例部署无此问题）
