# 浏览器端 E2E（v0.28）

> 之前只有 HTTP 层测试，UI 回归靠手点。这一轮加 Playwright 浏览器测试：
> **登录 → 工作台一键样例 → 审批页 → 退出**，并顺手修掉登录页的 CSP/密码泄露缺陷。

## 1. 运行

```bash
cd prototype
npm run e2e
```

- 优先用系统 Edge（`channel: 'msedge'`）；可用 `PLAYWRIGHT_CHANNEL` 覆盖
- 没有 Edge 时回退 Playwright 自带 Chromium（需 `npx playwright install chromium`）
- 不纳入 `npm test`（文件名 `e2e/ui.e2e.cjs`，避免默认发现）

## 2. 覆盖

`e2e/ui.e2e.cjs`：

1. 未登录打开 `/` → 跳到 `/login.html`
2. 断言登录页**没有内联 script/style**（CSP 兼容，且防止 JS 失效时密码进 URL）
3. 输入 alice/密码 → 登录成功，顶部显示用户名
4. 点击工作台样例「内网纪要」→ 出现「样例执行完成」
5. 打开 `#/approvals` → 页面渲染
6. 点退出 → 回到登录页；全程无 `pageerror`

## 3. 这轮修掉的真问题

登录页最初用内联 `<style>`/`<script>`，被控制台 CSP
（`default-src 'self'; style-src 'self'; script-src 'self'`）拦截后：

- 登录按钮退化成原生表单提交，**用户名/密码被拼进 URL**（`?username=...&password=...`）
- 脚本没执行，登录永远失败

修复：CSS/JS 拆成 `login.css` / `login.js`（同源外链），按钮改 `type="button"`，
表单 submit 只做 `preventDefault`；E2E 加断言防止回归。

## 4. 边界

- 只覆盖一条主路径，不覆盖 WS63/手机确认/附件上传
- 依赖本机浏览器；CI 需先安装 Chromium
- 没有截图对比/视觉回归
