# 附件安全：类型白名单 + 可选 ClamAV + 落盘加密（v0.24）

> 目标：附件不再“只看大小和哈希”。三层：
> **扩展名/魔数白名单** → **可选 ClamAV** → **AES-256-GCM 落盘加密**。
> 边界仍在文末，不把“扫过”说成“绝对安全”。

## 1. 类型与魔数

`src/file-scan.cjs`：

- 拒绝扩展名：`.exe .dll .sys .scr .com .bat .cmd .ps1 .vbs .js .jar .sh .py .rb .php .lnk .reg` 等
- 附件只允许：`.pdf .png .jpg .jpeg .gif .webp .txt .md .csv .docx .xlsx .pptx .zip`（无扩展名时按内容判断）
- 魔数：`MZ`（PE）/`ELF` 直接拒绝，即使改名成 `.pdf`
- 文档导入（`.txt/.md/.docx`）也过同一套检查；扩展名不支持时仍由 `importBuffer` 报“暂不支持”

## 2. ClamAV（可选）

| `SAFE_OFFICE_CLAMAV` | 行为 |
|---|---|
| `off`（默认） | 不调用扫描器，只做类型/魔数 |
| `auto` | 找到 `clamdscan`/`clamscan` 就扫；没有则标注“未扫描”但放行 |
| `required` | 扫描器不可用或扫描失败 → **拒绝附件** |

命中病毒 → `rejected`；扫描失败在 `required` 下也拒绝。

## 3. 落盘加密（AES-256-GCM）

- 环境变量 `SAFE_OFFICE_BLOB_KEY`：32 字节 base64 或 hex
- 新写入的附件内容：`SFE1 | nonce(12) | tag(16) | ciphertext`
- 读取时按魔数识别：有 `SFE1` 前缀就解密；旧明文附件仍可直接读（向后兼容）
- 未配置密钥 → 保持明文，文档明确标注；配置了但密钥错误 → 解密失败，拒绝发送
- `sha256` 仍对**明文**计算，冻结记录/发送前重算哈希不受影响

生成密钥：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

写进 `prototype/config.env`（gitignore），**丢失后新附件无法解密**。

## 4. 与发送链路的关系

- `_parseAttachments`：解码 → 空文件/大小 → 类型/魔数 → ClamAV → 通过才进入冻结流程
- 发送前 `DemoExecutor` 按 sha256 从 `BlobStore` 取内容（自动解密）→ SMTP 附件
- 附件元数据仍只存 `{name,sha256,size}`；加密密钥不进操作记录

## 5. 测试

`test/attachment-security.test.cjs` 4 项：类型/魔数、ClamAV required 拒绝、加密落盘/错误密钥、上传 `.exe` 拒绝。
全仓 **288 项全绿**。

## 6. 边界

- 魔数可伪造；白名单挡的是常见可执行文件，不是所有恶意内容
- ClamAV 结果依赖病毒库版本；默认 `off`，演示环境不要宣称“已杀毒”
- 加密只保护“库文件被直接拿走”的场景；运行中的进程仍有密钥
- 没有按用户/租户的访问控制；附件下载仍依赖操作批准状态
