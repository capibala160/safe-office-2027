# 账号安全体系：会话持久化、TOTP、管理员重置（v0.32）

> 2026-10-31 账号三件套。目标是把 v0.31 的「能改密」补成可日常使用的账号体系：
> 服务重启不掉登录、可选两步验证、管理员能重置他人密码。
> 本轮**没有**做租户隔离（下一轮 v0.33）与 ClamAV 安装（v0.34）。

## 1. 会话持久化

**改了什么**

- `AuthService` 新增 `sessionFile`（默认 `prototype/data/sessions.json`，已 gitignore）。
- 会话表只存 **token 的 SHA-256**，不存明文 cookie；文件权限 0600，写入走临时文件 + rename。
- 登录、登出、改密、管理员重置、过期清理时落盘；滑动续期最多每分钟落盘一次，避免每请求写盘。
- 启动时恢复：丢弃过期会话、用户表里已不存在的用户；**角色以用户表为准**，改角色后旧会话不会沿用旧权限。
- 恢复失败（文件损坏/格式不对）不阻塞启动：丢弃旧会话并记录 `sessionLoadError`，`npm start` 会打印警告。

**边界**

- 会话文件泄露 ≠ 直接可用：攻击者拿到的是哈希，不是 cookie；但能读文件的人可以改 expiry/角色字段（文件本身没有签名）。
- 仍是单进程内存 + 文件快照，不是 Redis/数据库会话。

## 2. TOTP 两步验证

**实现**

- 新增 `src/totp.cjs`：RFC 6238，HMAC-SHA1 / 30 秒 / 6 位；Base32 编解码、`otpauth://` URI。
- 用户表新增可选 `totpSecret` / `totpEnabled`（`users.json`，0600）；旧用户无字段自动按未启用处理。
- 登录：密码正确后，若已启用 TOTP，必须带正确动态码；缺码/错码统一返回 401（不区分，避免枚举）。
- 启用流程：`POST /api/2fa/setup` 生成密钥（只在内存 pending）→ 用户把 Base32 密钥/URI 加进认证器 → `POST /api/2fa/enable` 用当前动态码确认后才写盘。
- 关闭流程：`POST /api/2fa/disable` 需要密码 + 当前动态码。
- 限流：登录 5 次/分钟/IP；2FA 管理操作 5 次/分钟/IP。
- UI：顶栏「改密」弹窗里加「两步验证 · 管理」；登录页新增可选动态码输入。

**边界**

- 没有二维码渲染（只显示密钥/URI）、没有恢复码、没有设备记住/信任。
- TOTP 密钥明文存 `users.json`（0600）；能读该文件的人可以生成动态码。
- 仍是单因子 + TOTP，不是 WebAuthn/硬件密钥。

## 3. 管理员重置密码

- `AuthService.adminResetPassword(username, newPassword)`：不要求原密码；写回用户表；注销目标用户全部会话；清掉 pending TOTP。
- `GET /api/users`（管理员）：返回用户名/角色/是否启用 TOTP，不返回哈希或密钥。
- `POST /api/users/:username/reset-password`（管理员）：重置后目标用户必须用新密码重新登录。
- 治理页新增「用户管理」卡片（仅管理员可见），每行一个「重置密码」按钮。
- 非管理员访问以上接口一律 403。
