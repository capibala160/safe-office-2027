## 3. 明确不做 / 做不了（不是遗漏）

| 项 | 原因 |
|---|---|
| POP3 收信 | IMAP 已覆盖；维护两套协议无收益 |
| 跨 Agent 来源闭包 | 当前是单运行时多 Agent 身份模型；真正跨进程来源需要分布式信任根，超出 4C 范围 |
| 二进制附件内容分析 | 需要 PDF/Office 解析与 OCR 依赖；当前按「未分类」放行并审计 |
| 计划原文/板端原始帧落库 | 只存哈希与确认 ID，避免把模型输出和密钥材料写入长期存储 |
| 外部信任根（HSM/TEE） | 演示级 PSK；材料已写明不是 HUKS/TEE |
| CalDAV 手机端同步 | 需真 Android 手机（鸿蒙端 `-1`），属硬件/设备验证 |
| GitCode Actions | 平台内测未开通；公开 CI 证据用 GitHub 镜像 |
| >1h 长稳、WiFi 数据业务共存 | 硬件/时长验证项，不属于软件代码 |
| 真实继电器/锁体 | 缺实物；采购、接线与自检步骤已备好（[docs/80](80-真实继电器与锁体-采购接线验收-2026-11-17.md)，`npm run relay:test`） |

## 4. 封板含义

- 之后的改动应视为**新需求**，需要新的验收项；
- 任何「已完成」表述必须能指回上表或 docs/62 的证据；
- 演示前只需重跑一次 `npm run ci`，并确认两块板子在最新镜像上（协议 v2）。

## 5. 已知残余风险

- 真实模型评测的样本仍是 20 条验证攻击（95% 上界 13.9%，模型实际尝试子集上界 ~31%）；
- 污点规则 fail-closed，可能误伤已人工确认安全的派生内容；
- 回放页面依赖内存中的最近 50 次运行记录，更早任务需从审计归档重建（未实现）；
- 双板固件与 PC 工具必须同版本（协议 v2），混用会直接拒绝。
