# 管理员新增用户（v0.53.0 · 2026-11-19）

> 背景：控制台一直**没有注册功能**——账号只能由管理员用 CLI（`add-user.cjs`）预置，
> 治理页只能重置密码/禁用/删除，无法新增。本轮补上「管理员在治理页新增用户」，
> **仍不开放自助注册**（角色/租户/审计口径继续由管理员分配）。
>
> 结果：治理页「用户管理」新增表单 + `POST /api/users`（仅管理员）；新增 1 条 HTTP 测试、
> 1 条浏览器 E2E。全量 **633 项测试（631 通过 + 2 跳过）+ E2E 13/13**，lint / typecheck / strict 全绿。

## 1. 为什么不做自助注册

本项目是 Agent 安全治理演示：登录用户名同时是**租户**（文档/操作/审计按登录名隔离），
角色决定五道闸与审批权限。开放自助注册会引入：

| 风险 | 说明 |
|---|---|
| 角色不可控 | 注册者若能自选角色即可绕过策略矩阵（管理员/审计员） |
| 租户膨胀 | 任意注册即创建新租户，审计链、文档库、设备表都会被打散 |
| 滥用/刷号 | 公网部署时无邀请码的注册入口会被批量利用 |

因此保留「管理员建号」：既能在演示时当场加人，又不扩大攻击面。
自助注册 + 邀请码/待审批属于后续可选项（见 §5）。

## 2. 实现

| 层 | 改动 |
|---|---|
| `prototype/src/auth.cjs` | 新增 `AuthService.adminCreateUser(username, role, password)`：校验用户名/角色/密码 → scrypt 哈希 → **先落盘再改内存**（失败不留半状态） |
| `prototype/server.cjs` | 新增 `POST /api/users`（`requireRole` 仅「管理员」）；`mapAuthError` 增加 `USER_EXISTS → 409` |
| `prototype/public/views.js` | 治理审计页「用户管理」加表单：用户名 / 角色下拉 / 初始密码 + 「新增用户」按钮；成功后 `refreshState + rerender`，列表立即出现新账号 |
| `prototype/add-user.cjs` | 保留（CLI 仍是部署/救急入口，两者共用同一 `users.json`） |

### 2.1 校验规则（fail-closed）

| 规则 | 结果 |
|---|---|
| 用户名 `^[A-Za-z0-9_.@-]{2,32}$` | 否则 400（拒绝空格/中文/斜杠等进入审计与租户链） |
| 用户名已存在 | **409**（不覆盖已有账号；覆盖仍走 CLI） |
| 角色不在 `员工/实习生/审计员/设备助手/管理员/访客` | 400 |
| 密码少于 8 位 | 400 |
| 非管理员调用 | **403** |
| 未启用登录（无用户表） | 409 |

账号**即建即用**：无需重启服务；新账号首次登录后可自行改密（改密会注销其旧会话）。

## 3. 使用方式

**控制台**：管理员登录 → 侧栏「治理审计」→「用户管理」→ 填用户名/角色/初始密码 → 「新增用户」。

**CLI（部署/无管理员时）**：

```powershell
cd prototype
$env:SAFE_OFFICE_NEW_USER_PASSWORD='至少8位'
node add-user.cjs admin 管理员        # 第一个管理员
Remove-Item Env:SAFE_OFFICE_NEW_USER_PASSWORD
# CLI 写入 users.json 后需重启控制台才生效；治理页新增则即时生效
```

> 注意：**治理页表单只对「管理员」可见**。当前正式数据里只有 `alice`（员工）与 `auditor`（审计员），
> 没有管理员——第一次要先按上面 CLI 建一个管理员账号。

## 5. 边界（材料里如实写）

- **仍无自助注册**：账号必须由管理员创建（治理页或 CLI）。
- **用户管理动作未写入审计链**：新增/重置/禁用/删除沿用既有行为，只落 `users.json`，不进审计链；
  这是既有边界（非本轮引入），若要「管理员操作可追责」需单列一条审计事件——属后续增强。
- 用户名限制 ASCII；中文用户名不支持（租户名/审计字段会引入转义歧义）。
- 新增用户默认无两步验证；TOTP 仍由用户登录后自行绑定。
- 角色分配是信任前提：给谁「管理员」= 给谁全部管理权限；演示环境请少开管理员。
