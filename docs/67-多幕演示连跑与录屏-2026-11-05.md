# 多幕演示连跑与录屏（2026-11-05）

> 补上 [57](57-M3板端SFC1与串口CLI-2026-11-04.md) §6.6 明确记录的最后一个 M4 演示缺口：
> 「多幕演示连跑与录屏仍未做」。本轮把 8 个幕写成一条可复现的命令，真板连跑
> **8/8 全过**（20.4 秒），并录下整段过程；串口原始输出 905 字节中**没有出现任何启动标志**，
> 这是「连跑期间没有重启」的第一份直接证据。
> 基线：`271bed5`（strict 收尾提交）。

## 1. 一条命令

```bash
cd prototype
npm run demo:runthrough -- --port COM11
# 等价于 node scripts/demo-runthrough.cjs --port COM11
```

钥匙来源沿用 [60](60-一机一钥与安全存储-设计-2026-11-04.md) 的 `resolveDeviceKey`：
默认按设备标签 `ws63-A` 读 `data/devices.json`；也可以用 `--device ws63-B`、`--key <hex>`、
`--demo-key`（非生产）或 `SAFE_OFFICE_SFC1_KEY`。

可选参数：

| 参数 | 作用 |
|---|---|
| `--skip-software` | 跳过幕1 的 `demo.cjs`（只跑硬件幕） |
| `--skip-hardware` | 只跑软件多幕，不碰串口 |
| `--skip-press` | 跳过需要人按键的批准/取消两幕（自动化回归用） |
| `--out-dir <dir>` | 产物目录（默认 `out/demo-runthrough`） |

## 2. 幕目与实测

| # | 幕 | 判定 | 实测 |
|---|---|---|---|
| 1 | 软件多幕（`demo.cjs` 攻防演示） | 子进程退出码 0 | 1.12s |
| 2 | 设备执行：unlock → IO13 LED 亮 | ACK `pin=13 level=1`（绑定本次 nonce） | 0.67s |
| 3 | 设备执行：lock → IO13 LED 灭 | ACK `pin=13 level=0` | 0.67s |
| 4 | 批准：短按 KEY2 | `decision=1`，`confirmationId` 非空 | 3.84s（人工按键） |
| 5 | 取消：长按 KEY2 ≥600ms | `DECISION`（用户取消），不执行 | 4.06s（人工按键） |
| 6 | 超时：不按键 | PC 侧 `TIMEOUT` + 板端 `pending expired` | 6.69s |
| 7 | 篡改：MAC 末字节翻转 | 板端 `SFC1 challenge rejected: MAC` | 0.62s |
| 8 | 重放：过期后重发同一帧 | 板端 `SFC1 challenge rejected: REPLAY` | 2.74s |

合计 **20.4 秒**，8/8 通过。产物：

```text
prototype/out/demo-runthrough/20261105-022123/
  summary.json      # 逐幕结果、耗时、串口字节数、重启标志
  run.log           # 控制台全文
  serial.txt        # 板端串口原始文本（905 B）
  serial-raw.bin    # 板端串口原始字节
```

## 3. 录屏

- 文件：`桌面\安全智慧办公2027_演示录屏_2026-11-05\多幕演示连跑_2026-11-05.mp4`
- 规格：**34 秒**，2560×1600，10 fps，H.264（约 3.2 MB）
- 内容：窗口就绪倒计时 → `demo.cjs` 软件多幕 → LED 亮/灭 → 批准/取消/超时/篡改/重放 →
  8/8 结果页；画面停在结果页，便于答辩时暂停讲解。
- 同目录附 `summary.json` / `run.log` / `serial.txt`，录屏里的数字可与日志逐条对上。

录制方法（可复现）：

```powershell
# 1) 在独立窗口里跑演示，窗口先等 6 秒，便于录制对准
wt.exe -w -1 nt --title "SFO-DEMO" powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts\demo-window.ps1 -Port COM11
# 2) 录桌面（ffmpeg 来自 imageio-ffmpeg，本机无独立 ffmpeg）
ffmpeg -f gdigrab -framerate 10 -i desktop -t 80 `
  -vf "scale=trunc(iw/2)*2:trunc(ih/2)*2" -c:v libx264 -preset ultrafast -crf 28 `
  -pix_fmt yuv420p out/demo-recording.mp4
```

> 录制坑：Windows 11 的 Windows Terminal 是 GPU 渲染，`gdigrab -i title=SFO-DEMO`
> 抓出来是**黑屏**（窗口标题存在但 GDI 表面为空）；必须录 `desktop`，并让演示窗口处于前台。
> 演示窗口放在独立窗口（`wt -w -1`）而不是 Claude/终端里的标签页，避免录制时被切走。

## 4. 「无重启」的判定口径

监听在幕2（设备执行）之后开启，之后全程保留串口原始字节。结束时扫描以下启动标志：

```text
Enter board confirm (M3)! / M3 SFC1 ready: / Create KeyTask is OK!
SFC1 KEY: provisioned / SFC1 KEY: DEMO / SFC1 NV: restored / SFC1 NV: empty replay window
```

本轮 **0 命中**（`restartMarkers: []`，`rebootDetected: false`）。

边界（如实写）：

- 这证明**幕2 之后**没有出现启动日志；设备执行幕要独占串口，发生在监听开始之前，
  所以它自身的几秒钟没有串口证据。
- 不是复位计数器：如果板子在监听间隙重启且启动日志没被读到，本方法看不到。
- 按键幕的判定包含人工操作；视频里能看到提示与结果，但按的是物理按键，画面不显示手部动作。

## 6. 已知坑（写在这里避免重复踩）

1. **串口互斥**：批准/取消/超时幕复用同一个 `SerialTransport`；设备执行幕必须在前，
   因为它要自己开串口（执行器 `Access denied` 的根因见 [65](65-设备联动真板执行-2026-11-04.md)）。
2. **迟到决定帧**：上一幕的超时按键会在下一幕到达，`acceptDecision` 以 `TASK/NONCE`
   拒绝。运行器会把这类帧当作过期帧重试，不算失败，也不污染下一幕。
3. **Windows Terminal 录屏**：见 §3 的坑；`-i title=...` 不可用。
4. **PowerShell 5.1 编码**：`.ps1` 含中文时必须存 UTF-8 **带 BOM**，否则按 ANSI 解析报
   「字符串缺少终止符」。`demo-window.ps1` 已带 BOM。
5. **MSYS 路径转换**：Git Bash 会把 `/k` 转成 `K:/`；在 `cmd` 参数里用 `//k` 或改用 `.cmd` 包装。
