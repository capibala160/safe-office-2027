## v0.7 新增（2026-10-16 · 健壮性闭环 · F-05 + F-06 整改）

| 问题 | 本轮实现 | 验证与限制 |
|---|---|---|
| F-06 模型异常向上抛出 | 统一 fail-closed：模型故障归一为固定类别（超时 / 网络故障 / HTTP错误 / 非法JSON / 空响应 / 未配置 / 边界拒绝，`faults.cjs`）；规划失败 → 零执行 + 「规划失败」审计（含类别与原始原因）+ 用户可见结果；执行中模型故障 → 「任务中止」，其后步骤一律不执行、不崩溃 | 故障注入基于本地假端点（离线真实 HTTP 栈）；联网真实模型的长期行为（限流、重试风暴、半包）仍需验收 |
| 超时重试可能重复执行 | 任务级幂等键（taskId）：同一 taskId 只执行一次；任何终态（含失败）都复用首次结果；换指令/换角色 = 幂等冲突拒绝；执行中并发重复 = 幂等拒绝 | 幂等记录为进程内内存；持久化与跨设备幂等（上板后）未实现；要真正重试须换新 taskId（标准幂等契约） |
| 令牌跨任务残留 | 任务结束（成功/失败/异常）自动吊销令牌并审计；`autoRevoke:false` 显式关闭（仅限确需跨命令共享令牌的调用方） | 自动吊销只覆盖 `runCommand` 入口；直接调用 `execStep` 的路径由调用方负责令牌生命周期 |
| F-05 云侧目标脱敏与授权匹配冲突 | 云侧指令中地址/链接 → `[目标N]` 占位符，真实值只留端侧；模型计划引用占位符 → 端侧回填真值 → 授权校验仍锚定用户指令原文（模型可发送的目标 ⊆ 用户输入过的目标）；未登记占位符/编造地址一律移除 | 占位符只覆盖指令文本（用户明确输入的目标）；文档正文中的地址仍按脱敏规则处理；真实模型对占位符协议的实际遵循度待联网验收（提示词已注明） |

| 确认凭据过宽 | 新增 nonce、30 秒有效期、操作和最终出站内容哈希绑定、HMAC 校验及一次性消费 | 当前 response 由主机模拟，不是硬件安全保证；真实节点应持有独立密钥并主动确认，不允许将模拟签名函数暴露为生产接口 |
| 外发伪回滚 | 回滚只恢复本地知识库，保留已发送/已上传记录 | 真实邮件、打印和物理动作不可由内存快照撤回；真实工具需发送前暂存及补偿流程 |
| 审计不足 | SHA-256 完整摘要、序号校验、链头/条数检查、文件保存和可信检查点恢复 | 检查点必须独立可信保存或签名；同文件里的检查点不能证明整链未被替换；尚无 HUKS 签名或抗回滚存储 |
| 策略实例污染 | 默认策略深拷贝，更新时验证决策值 | 当前管理员身份由调用方保证，未实现登录及审批后台 |

补充（v0.6 口径，仍有效）：计划校验限制 64 步，必需参数必须是非空且不超过 2048 字符的字符串。图片/OCR、语音转写、邮件和设备执行仍使用模拟素材/副作用；资源策略校验尚不是操作系统级执行沙箱。低层令牌校验通过会消耗配额，即使后续沙箱或数据检查拒绝；不能把配额描述为"成功执行次数"。

## 近期收敛范围

核心交付限定为"授权纪要读取 → 模型整理正式稿 → 继承密级 → 最终内容与目标确认 → 测试邮箱发送 → 持久化审计"。其他办公能力保留模拟验证，避免八条业务同时做实。

### 里程碑一：真实模型与真实工具闭环

1. 在隔离测试环境配置 HttpLLM，使用自建虚构材料；不使用真实企业机密。
2. 真实调用前记录部署位置、输入密级和请求数据类别，避免日志记录正文或凭证。
3. 将 outbox 模拟替换为测试邮件适配器，增加发送前暂存、最终预览、幂等键和超时结果查询；一次确认只授权一个最终版本。
4. 检查超时、模型返回非法 JSON、空结果、重复执行、生成后目标变化、源材料更新和断网恢复。
5. 输出可复现日志与端到端录屏。未完成前不得宣称真实办公系统已跑通。

> v0.7 进展：第 4 项的**替身演练**已完成（假端点覆盖超时/非法JSON/空结果/重复执行/断网恢复，见 v0.7 新增）；第 1–3 项（联网真实模型、测试邮件适配器、持久化审计）未开工。

### 里程碑二：最小硬件验证（提前于全面移植）

> **口径变更后**：以下 6.0.0.1 要求仅适用于选择 6.0.0.1 路线；若走 4.x/5.x，按同等步骤验证，版本以实际镜像为准。主设备本身可选，Node + WS63 路线不阻塞。

1. 若走 6.0.0.1 路线，采购前取得目标板 **OpenHarmony 6.0.0.1 Release** 的镜像、构建版本证据、烧录步骤和对应 SDK；若走 4.x/5.x，取得该版本对应证据即可。版本号以实际镜像与 `param get` 为准。
2. 验证系统启动、hdc、ArkTS 空应用；分别验证文件、网络、密码学和权限接口，不能将商业 HarmonyOS 开发经验直接视为 OH 兼容证据。
3. 单独验证 HUKS 签名、重启后验签、密钥不可导出和实际保护级别。HUKS API 可用不等于该板具备 TEE 硬件保护。
4. 若主板无可用 SLE 接口，验证 `OH 主板 → USB/UART → WS63 网关 → SLE → WS63 确认节点`。主板到网关的驱动、协议、断线和信任边界都要测试。
5. 节点展示/关联最终操作，由持有者按键确认；测试错误 MAC、重放、超时、断线、错节点、内容替换。
6. SLE 连通和 RSSI 不构成可靠距离证明；当前不声称防中继或本人身份认证，扫码/NFC 备用路线同样不能自动获得这些保证。

## 评测方案

使用同一批正常任务与攻击样本，对比无防护、仅提示词防护、完整网关。外部动作全部接隔离测试工具。

记录攻击成功率（越权副作用实际发生）、正常任务完成率、误拦率、每任务确认次数、安全逻辑耗时、模型耗时、确认等待和总任务耗时；报告 P50/P95、样本量、设备、模型版本与失败样例。分离开发样例和未参与调参的验证集，并单独展示各安全层的消融结果。

现有 Node 测试与 demo 只能证明原型逻辑，不代表模型攻击成功率或板端性能。当前性能采集包含"规划+校验"，不得将其总和称为纯安全开销。

> **v0.8 进展**：三档对比已实现为 `npm run eval`，指标含攻击成功率、完成率、误拦率、确认次数、模型/安全/确认等待/总耗时（P50/P95）、样本量与设备信息，并输出失败样例。**单层消融尚未实现**，当前只有"各层拦截贡献"的描述性统计。离线跑分基于 Mock，真实模型须用 `--llm=http` 复测。
