## 2. CI 矩阵 + 覆盖率

`.github/workflows/ci.yml` 重写为 4 个 job：

| job | 内容 |
|---|---|
| `test` | **ubuntu + windows** 矩阵（Node 24）；Linux 跑 `node --test --experimental-test-coverage` 并上传 `coverage.txt`；Windows 跑 `npm test` |
| `quality` | lint + typecheck + strict + Playwright E2E |
| `audit` | `npm run audit`（高危阻断） |
| `docker` | 构建镜像 → 起容器 → 轮询 `/api/health` → 失败打印日志 |

> **为什么不是 Node 20/22/24**：项目依赖 `node:sqlite`，Node 20/22 不支持（22 早期还需 flag）。
> 用 **OS 矩阵**（Linux + Windows）证明可移植性更真实——本机就是 Windows。

覆盖率：使用 Node 24 内置 `--experimental-test-coverage`，不引入新依赖；
**2026-11-19 复核实测**（`cd prototype && npm run coverage`，Windows / Node 24.15）：
全量**行覆盖 88.12% / 分支 75.59% / 函数 88.74%**（`runtime.cjs` 99.20%、`task-replay.cjs` 96.10%、
`server.cjs` 77.65%、`console-service.cjs` 93.52%、`ws63-protocol.cjs` 96.49%）。
口径说明：只统计单测/集成测试加载到的模块，**E2E 不计入**，且是 Node 实验性覆盖率
（不是 Istanbul/c8 全量口径），对外仍注明「行覆盖约 88%（不含 E2E）」，不写「100%/生产级覆盖率」。

> 历史数据：2026-11-17 文档曾记录「约 48%（runtime.cjs 51%、ws63-protocol.cjs 12%）」，
> 该数字在 2026-11-19 无法复现（实测见上），已按实测口径修正。

## 5. 发布打包

`npm run release` → `dist/safe-office-<version>-<日期>.tar.gz` + `.sha256` + `MANIFEST.json`。

| 项 | 说明 |
|---|---|
| 包含 | README、Dockerfile/compose、docs/、ws63/、prototype/、.github/ |
| 排除 | node_modules、.git、data/（钥匙/设备表）、out/、dist/、config.env 等私有件 |
| 清单 | `MANIFEST.json` 记录 version/commit/createdAt/文件数 |
| 实测（2026-11-17 首包） | 4.25 MB、330 文件、commit `86aaba9`、sha256 一并生成 |
| 实测（2026-11-19 重打） | 同一脚本按最新 HEAD 重打包（日期后缀 `20261119`），文件数/体积同级，sha256 一并生成；**交付以最新包为准**，旧包 sha256 `c07db727…` 只对应旧提交 `86aaba9` |

> Windows 的 GNU tar 对 `C:\` 与中文路径不稳定：脚本先在临时目录生成 ASCII 文件名再复制，
> 保证 Windows/Linux 都能跑。
