# v0.17 · 草稿编辑与任务进度（2026-10-29）

> 解决的问题：安全机制已经完整，但日常流程（导入资料 → 起草 → 人工修改 → 确认 → 导出）仍像演示台。
> 本轮只做「让已有能力可靠好用」的部分，不新增业务能力。

## 1. 草稿编辑与重新确认

**流程**：命令产出冻结操作 → 审批页直接改正文 → 哈希重算 → 旧确认/挑战作废 → 重新发起确认 → 批准后导出。

| 项 | 实现 |
|---|---|
| 接口 | `POST /api/operations/:id/body`（`{ body, editor, note }`）、`GET /api/operations/:id/revisions` |
| 允许条件 | 仅 `frozen`（尚未确认）。已确认/已执行/已拒绝的记录**不能改**——否则等于绕过确认，只能新建 |
| 哈希 | 用 `sealOperation` 重新封印：`bodyHash`、`operationHash` 全部重算，`verifyOperation` 必须通过才落库 |
| 旧确认 | 该操作所有 pending 挑战置为 `expired` 并 `confirmer.cancel`；设备侧 pending 一并取消 |
| 版本 | 新表 `operation_revisions`：每次编辑把**被替换的版本**（正文/两个哈希/编辑人/备注）存档 |
| 审计 | 追加 `草稿修改`（旧哈希→新哈希、作废挑战数、编辑人）与 SQLite `草稿修改` 事件 |
| 前端 | 审批页冻结操作显示可编辑正文框 + `vN` 版本历史（行级 diff，`UI.diffLines`） |

**边界**：正文仍以明文存 SQLite；附件不能在这一步增删（改附件需新建操作）；编辑不延长 TTL。

## 2. 任务进度与取消

命令不再只能"转圈等结果"。

| 项 | 实现 |
|---|---|
| 异步接口 | `POST /api/commands/async` 立即返回 `runId`；`GET /api/commands/:runId` 轮询；`POST /api/commands/:runId/cancel` 取消 |
| 阶段 | `排队 → 规划 → 执行 i/n → 待确认 / 完成 / 失败`，`stageLog` 记录每一步时间点 |
| 取消语义 | 只在**步骤之间**生效：当前步骤跑完即停，后续步骤不执行；`任务取消` 进审计（含已执行步数、未执行步数） |
| 已发生副作用 | 不回滚、不伪造撤回——已执行的步骤保留记录，与回滚能力分开 |
| 离开页面 | 服务端任务照常跑完；前端把 `runId` 记在 localStorage，回到命令台自动接上进度 |
| 兼容 | 原同步 `POST /api/commands` 与 `service.runCommand` 保持不变（测试、demo 不受影响） |

**边界**：取消不能中断进行中的模型调用（HTTP 请求本身不可撤回），只在模型返回后的步骤间生效；阶段是粗粒度，不做 token 级流式。

## 3. 顺手修掉的问题

| 问题 | 处理 |
|---|---|
| 取消全部勾选反而扩大授权 | `tools`/`documentIds` 区分「未传 = 角色默认」与「显式空 = 不授权」；工具显式为空直接 400 |
| 导入后授权列表不更新 | 导入成功先 `refreshBootstrap()` 再重渲染，命令台立刻能看到新资料 |
| 超过 5 个附件被静默截断 | 改为明确报错「附件最多 5 个（当前选了 N 个）」 |
| 顶栏模型状态写死 | 改读 `state.model`：显示真实模型名 + 部署位置（云/本地），`title` 显示模式说明 |

## 5. P1 三项（同轮完成）

### 5.1 确认端展示完整操作

- `GET /api/phone/state` 的 `pending.details` 带：收件人/目标、密级、正文预览（前 600 字 + 总字数）、附件名与大小、`targetHash`/`bodyHash`、`verify`
- 手机端解码挑战帧后，把 `details.targetHash` 与帧里的 `operationHash` 比对，**不一致直接拒绝确认**
- 页面同时标注：正文内容由控制台提供，端上校验的是目标哈希——不把"服务器给的详情"说成"端上验证过"
- 边界：详情不在 SFC1 帧内（帧长固定），所以内容真实性仍依赖控制台；端上只保证"你批的就是挑战里那条操作"

### 5.2 文件页直接发起任务

- 文件列表每个文档旁加「整理纪要 / 起草邮件」，点击带入该文档的授权（`tools` + `documentIds`）跳到命令台
- 命令台沿用 `pendingSample` 预填机制；用户仍可在执行前改勾选

### 5.3 重启后完整恢复

| 数据 | 存哪 | 说明 |
|---|---|---|
| 操作来源 | `operation_meta` 表 | runId / 步骤号 / 文档标题 / 参数 / 审计区间，按条写入 |
| 运行历史 | `console_state('console')` | 最近 50 条 run（含 gateSummary、operations） |
| 风险计量 | 同上 | score / events / frozen / freezeCount / reviews |
| 业务状态 | 同上 | 删除文档集合 / 打印 / 设备指令与状态 / 日历 / 自动模式 |

- 恢复结果通过 `getState().recovery` 暴露，**不往审计链里追加恢复事件**（审计保持"只记动作"的语义，也避免破坏既有链长断言）
- 边界：行为因子的滑动窗口（10 分钟观测）不恢复，重启后重新累积；恢复失败只记录在 `recovery.error`

测试：新增 1 条跨进程恢复用例（临时文件库 → 关闭 → 重开 → 校验操作来源/运行历史/风险冻结/操作状态）。
