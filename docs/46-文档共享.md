# 文档共享（v0.41）

> 租户隔离（v0.33）让每个账号只看到自己导入的资料，但办公场景里"把资料给同事看"
> 是真实需求。v0.41 把「共享」从界面上的模拟动作变成**真实的、可撤销的授权**：
> 所有者按人授权、密级不因共享而降低、撤销立即失权并清除已读副本，全程写审计链。

## 1. 规则

| 规则 | 说明 |
|---|---|
| 谁能共享 | 只有**文档所有者**或**管理员**；其他人（含审计员）一律 403 |
| 共享给谁 | 已存在的登录账号（可选角色：员工/实习生；管理员/审计员本来就可见全部文档）；不能共享给自己或所有者本人 |
| 密级 | 共享**不降密级**：目标账号的角色必须本来就能读这个密级（机密文档不能共享给只能读公开/内部的实习生） |
| 样例文档 | 无 owner 的样例文档对所有角色可见，共享返回 409（无需共享） |
| 撤销 | 撤销后被授权人立即从列表/详情/命令授权中消失；已读进知识库的副本一并清除 |
| 审计 | `文档共享` / `取消共享` 两条事件，含文档、所有者、被授权人、角色、密级、清除副本数 |

## 2. 数据模型

`prototype/data/documents.db` 新增表（与文档同库，重启不丢）：

```sql
CREATE TABLE IF NOT EXISTS document_shares (
  doc_id     TEXT NOT NULL,
  grantee    TEXT NOT NULL,
  granted_by TEXT NOT NULL,
  granted_at TEXT NOT NULL,
  PRIMARY KEY (doc_id, grantee)
);
```

- 重复授权是幂等的（更新授权人/时间，不产生第二条）。
- 删除文档时同步删除其共享记录（`DocumentStore.delete`）。
- 授权只是"额外允许某个账号读"，不改变 `documents.owner`、不移动文档。

## 3. 可见性接入点

共享授权接入四处口径，保证"列表能看到"和"命令能读到"一致：

1. `ConsoleService._docRowVisible` → 文档列表 / 详情 / 计数；
2. `ConsoleService._docVisibleTo` → 命令页文档授权列表 + 令牌签发前的租户过滤；
3. `Token.documentIds` → 闸2 数据访问检查（读正文必须持令牌）；
4. 角色密级（`roleDocIds`）仍是硬上限——共享不能把文档提升到角色读不了的密级。

## 4. API

| 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|
| GET | `/api/share-targets` | 员工/管理员/审计员 | 可共享的账号列表（仅 username/role） |
| GET | `/api/documents/:id/shares` | 同上 | 文档的共享列表（所有者/管理员） |
| POST | `/api/documents/:id/share` | 同上 | `{ grantee }` 授权 |
| POST | `/api/documents/:id/share/revoke` | 同上 | `{ grantee }` 撤销 |

未启用登录（没有用户表）时，共享接口返回 409，前端也不显示共享按钮。

## 5. 界面

文件页每行对"自己的文档"显示「共享」按钮：

- 面板列出当前被授权人、角色、授权人、时间，可逐个撤销；
- 被共享的文档在对方文件页的「归属」列显示 `alice（共享给我）`；
- 共享/撤销后刷新 bootstrap，命令台的授权文档列表立即跟着变。

## 7. 边界

- 共享对象是**登录账号**，不是"链接"：没有公开链接/匿名访问。
- 没有过期时间与访问次数上限；撤销是唯一的回收手段。
- 管理员可以为任何人的文档授权（治理需要），但同样受密级约束。
- 被授权人读过的正文会进入进程内知识库；撤销时按 `owner + sourceIds` 清除，
  但**已经导出/发送出去的内容无法回收**。
- 撤销**不会自动作废**对方已经冻结、尚未确认的操作（内容在授权期内已合法读取）；
  需要时由审批人驳回。撤销只回收"继续读取"的权利。
- 共享不改变审计链的租户过滤：被授权人能看到文档，但看不到所有者的操作历史。
