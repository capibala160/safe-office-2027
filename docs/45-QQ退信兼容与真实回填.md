# QQ 退信兼容与真实回填（v0.40.2）

> 真实 Gmail 退信终于到了（INBOX UID 422，2026-10-31 11:13，收件人
> `safe.office.bounce.9f3a2b7c@gmail.com`）。它暴露了三个只有真实环境才会出现的问题：
> ① QQ 退信不是标准 DSN 结构；② QQ 改写了原始 Message-ID；③ 用户先点开退信会变成已读，
> 只扫未读就会漏掉。本轮全部修复并完成真实回填。

## 1. QQ 退信长什么样

```
Content-Type: multipart/report; boundary="QQ_MAIL_RETURN"; report-type=delivery-status

--QQ_MAIL_RETURN
Content-type: text/html        ← 人类可读：无法发送到 / 退信原因 / host ... said: 550-5.1.1 ...
--QQ_MAIL_RETURN
Content-Type: application/octet-stream; Content-Transfer-Encoding: base64
                              ← 被退回的原信（base64）
```

- **没有** `message/delivery-status`：旧解析器识别为 DSN 但拿不到任何收件人状态。
- 原信里的 `Message-ID` 被改写为 `<tencent_xxx@qq.com>`，与我们发信时记录的
  `<xxx@qq.com>` 对不上。
- 但原信保留了 `X-Idempotency-Key`（我们发送时写入的 `operationHash`），且 QQ 原样保留。

## 2. 修复

**解析器（`src/dsn.cjs`）**

- 支持 QQ 的 HTML 退信正文：提取收件人、`5.x.x` 状态、`host ... said:` 诊断信息。
- 支持 base64 的 `application/octet-stream` 原信：解码后读原信头。
- 从原信提取 `X-Idempotency-Key`（仅接受 64 位十六进制），随报告返回 `idempotencyKeys`。
- 标准 RFC 3464 退信行为不变。

**匹配（`store.cjs` / `fulfillment.cjs` / `console-service.cjs`）**

- 新增 `listOutboxByIdempotencyKey`（outbox 的 `idempotency_key` 就是 `operationHash`）。
- 回填顺序：**Message-ID 优先 → 幂等键回退**；命中后记录 `matchedBy`。
- 两者都命不中才报 `unmatched`，不做任何猜测。

**轮询（`src/imap-poller.cjs`）**

- 候选邮件 = 未读 + **最近 7 天全部邮件** + 主题/发件人提示。
  QQ 对中文主题搜索不返回结果，因此必须有"最近窗口全扫"的兜底。
- 已读退信（用户先点开过）也能处理；处理过的 UID 记入内存，不再重复抓取。
- 普通邮件仍不标已读，只记 UID 跳过。

## 3. 真实回填结果

用真实退信（已读、Message-ID 已被改写）跑 `pollBounceNow`：

```
scanned=97  dsn=1  bounced=1  ignored=96  errors=0
outbox: bounced
matchedBy: idempotencyKey
diagnostic: 550-5.1.1 The email account that you tried to reach does not exist ...
审计链有效：true
```

`退信` 审计里记录收件人、5.1.1、完整诊断、`idempotencyKey`、outboxId/operationId；
`messageId` 为空（因为被 QQ 改写，实际是靠幂等键命中的）。

## 4. 验证

```bash
npm test      # 375 项：373 通过 + 2 跳过（ClamAV / 真实 Edge 默认跳过）
npm run e2e   # 7 项
```

新增 3 项回归：

- QQ 格式解析（HTML + base64 原信 → 收件人/状态/诊断/幂等键）；
- Message-ID 被改写时用幂等键回填；幂等键也对不上则 `unmatched`；
- 已读退信也能处理，且第二轮不重复抓取。

## 5. 边界

- 幂等键回退依赖 MTA 保留 `X-Idempotency-Key`；QQ 会保留，但不是所有 MTA 都保证。
- 最近窗口固定 7 天；更早的已读退信不会被自动扫描（可手工导入 `.eml`）。
- 每次进程重启后，最近 7 天的普通邮件会被重新抓取一次（内存忽略集不落盘）——
  有带宽成本，但没有重复回填（退信会按 duplicate 处理）。
- QQ 退信的 `Status` 从 HTML 文本提取；如果 QQ 改版措辞，解析可能退化到 `unmatched`（会明确报告）。
- 真实退信只验证了「QQ 收 Gmail 退信」这一种组合；其他 MTA 格式仍以标准 RFC 3464 为主。
