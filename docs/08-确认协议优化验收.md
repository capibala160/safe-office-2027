# 确认协议优化与验收

更新：2026-10-17。范围为 PC 可验证的协议与状态机，未进行 WS63 烧录、SLE 或真实邮件联调。

## 已实现

1. C 新增 `proto_accept_bound_decision`：核对可信配置中的设备 ID，以及最终执行记录中的动作、操作哈希，再完成 MAC、任务号、nonce、时效和一次性校验。旧入口保留兼容，板端接入示例已切换到绑定入口。
2. pending 未过期时拒绝新任务覆盖；过期后消费旧 nonce。TTL=0、时间加法溢出拒绝，截止时刻即过期。
3. 帧头不接受未知 flags/reserved。
4. 新增 Node SFC1 编解码器：与 C 使用相同布局、16B nonce、32 位秒时间戳、HMAC-SHA256；检查长度、MAC、摘要 UTF-8 字节上限及字段范围。
5. 新增 Node/C 双向编解码固定向量校验，以及错设备、操作变化、忙碌覆盖、过期边界、TTL 溢出等回归测试。
6. C 端同步补齐与 Node 对齐的语义校验：摘要禁止 NUL、拒绝非法/overlong/代理区/超范围 UTF-8；challenge 必须 `expires_at > issued_at`；decision 只接受 0/1。新增对应回归用例。
7. action 只允许 1–4（C/Node 同步校验）；设备/最终操作绑定检查移到 MAC 校验之后，错误 MAC 不再通过错误码泄露绑定信息。

## 验证

- `prototype` 下 `node --test`：该轮 100 通过、0 失败、0 跳过，包含 gcc 编译的跨语言测试；v0.10 新增闭环 9 项后 109 项；v0.11 新增适配器 14 项后 123 项；v0.12 新增控制台 34 项（控制台 20 + HTTP 14）后 157 项；v0.13 新增工具注册表/MCP 16 项后当前 **173 项**。
- C：`gcc -std=c11 -Wall -Wextra -Werror -O2 ...` 严格编译通过，`test_protocol` 输出 `PASS: all protocol tests`；摘要 NUL/UTF-8、生命周期、decision 值域、action 范围、MAC 先于绑定检查用例均已覆盖。
- 跨语言测试使用 Node 的真实 HMAC 生成向量，C 的回调核对固定向量的 MAC 输入并返回已知 MAC；证明编码布局一致，不证明 C 密码学实现正确。

## 下一步接入契约

- 唯一操作记录包含角色、动作、精确目标、最终正文/附件摘要和任务标识；PC 冻结记录并计算哈希，节点展示关联摘要。任何修改须重新确认。
- `expected_device` 从可信配对配置取得；最终动作和哈希从冻结记录取得，不能直接复用应答字段作为期望值。
- 执行端以自身时钟判定有效期，无须将确认端开机时间与执行端时间比较。
- C 层只处理已计算好的 32 字节哈希；JSON 序列化规则和操作哈希生成尚未统一成跨平台规范，不能把编解码器称为完整协议集成。
- Node 运行时仍使用原模拟确认；串口传输、SLE、GPIO、节点显示、板端真实 HMAC、持久化审计待完成。
- 不提供距离证明、本人身份认证或防中继保证。

## 后续加固（本轮未做）

- **每设备独立密钥/配对流程**：当前为单预共享密钥，设备 ID 只是标识；多设备部署应一机一钥。
- **nonce 窗口持久化**：当前 8 条窗口在 RAM，重启丢失；节点重启会废弃 pending，跨重启防重放未实现。
- **板端实测**：SLE/串口传输、mbedTLS HMAC、GPIO/按键、显示与 Flash 审计均未联调。
