## 1. 一键演示包（P1）

```bash
cd prototype
npm run demo:start    # 建演示数据 + 演示账号 + 启动控制台
npm run demo:reset    # 先 Ctrl+C 停止，再清空演示工作区并重启
npm run demo:check    # 只建演示数据并退出（CI/自检）
```

- 数据全部隔离在 `prototype/data/demo/`（已 gitignore），不碰正式 `data/`
- 演示账号：
  - 管理员 `demo-admin / DemoAdmin2026!`
  - 审计员 `demo-auditor / DemoAuditor2026!`
- 演示模式强制 `SAFE_OFFICE_AUTH=required`，并关闭真实 SMTP / IMAP / 打印机 / 真实模型，避免误发
- 内置样例、文档、日历种子直接可用；治理页「重置演示」可一键清空工作区
- 地址：`http://127.0.0.1:7812`

## 2. 审计归档 / 轮转 / 保留（P2）

- 新增 `rotateAudit()`：先把活动审计 `.jsonl`、`.head`、`.tenants` 复制到 `audit-archive/audit-<时间>.jsonl*`，再清空活动链并写一条 `审计轮转`（记录 previous 检查点与归档路径）
- `pruneAuditArchives({keep})`：只保留最近 N 份归档（默认 14），整组删除更旧的 `.jsonl/.head/.tenants`
- 启动时按 `SAFE_OFFICE_AUDIT_RETENTION_DAYS` 自动轮转；`SAFE_OFFICE_AUDIT_ARCHIVE_DIR` 可配置归档目录、`SAFE_OFFICE_AUDIT_ARCHIVE_KEEP` 配置保留份数
- 管理员 API：`POST /api/audit/rotate`、`POST /api/audit/prune`；治理页有「轮转审计」按钮
- 边界：轮转不删除旧链，旧链在归档目录独立保存；新链通过 `审计轮转` 的 `previous` 记录与旧检查点关联

## 3. 邮件回信草稿 + 发件账号 UI + 告警 webhook（P3）

- **回信草稿**：`POST /api/mail/reply-draft` 读取收件箱指定 uid，返回 `{to, subject, body}`，`autoSend:false`；收件箱每封邮件有「起草回复」按钮。**只生成草稿，不自动发送**；发送仍需另行走审批/确认。
- **逐次选发件账号**：`getBootstrap()` 返回 `mailAccounts`（不含密码），邮件页显示账号下拉；命令携带 `mailAccount`，冻结时固化并进入 `operationHash`。
- **告警 webhook**：`scripts/healthcheck.cjs` 支持 `--webhook=` 或 `SAFE_OFFICE_ALERT_WEBHOOK`，失败时 POST `{text, checks}`；`deploy/README.md` 已给 cron 示例。
- **GitCode CI**：`.gitcode/workflows/ci.yml` 已加；当前无法从本地确认 GitCode 是否识别该目录，**本地 `npm run ci` 为权威口径**，材料里不要写「GitCode CI 已跑通」。

## 4. 模拟边界（材料必须如实写）

- `shareScreen` 只输出「已开启」，不是真实投屏/WebRTC
- `transcribeAudio` 返回模拟文本，不是真实 ASR
- 租户 = 登录用户名，不是组织/企业
- 闸4 的 `nearfieldOnline` 仍是模拟确认；WS63 上板后替换
- 收件箱只读：不标已读、不自动回复、不执行邮件内容；回信只生成草稿
- 评测为单模型（GLM-5.3-Flash）、validation 14 条、本地适配器，比率只代表本轮样本
