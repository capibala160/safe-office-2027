# 设备联动真板执行（v0.52，2026-11-04）

> 目标：把 `deviceControl` 从「冻结→确认→只记录」变成**确认通过后由 WS63 真板执行 GPIO**。
> 只驱动两个可观测输出：**IO13 板载 LED**、**IO10 蜂鸣器**；没有继电器/锁体，不宣称真实开锁。
>
> **2026-11-05 更新**：新增 **IO12 继电器输出**（默认关闭），主机侧用
> `SAFE_OFFICE_ACTUATOR_RELAY_PIN=12` 开启；固件已编译，尚未烧录/接线。详见
> [68-继电器与锁体支持](68-继电器与锁体支持-2026-11-05.md)。

## 1. 链路

```
控制台冻结 deviceControl → WS63/手机/虚拟确认（SFC1 DECISION）
  → 执行操作 → ConsoleService._applyBusinessAction(protocolAction=4)
  → src/device-actuator.cjs 组装执行帧（0x21，HMAC-SHA256 + 16B nonce）
  → 串口 → 板端验签 / nonce 查重 → 驱动 GPIO → 回 ACK（0x22）
  → 审计「设备执行」；失败写「设备执行失败」并转 unknown（不自动重试）
```

## 2. 协议扩展（`ws63/protocol.h/.c` + `src/ws63-protocol.cjs`）

| 帧 | type | payload |
|---|---|---|
| 执行帧 | `0x21` | `nonce(16) + pin(1) + level(1)` + MAC(32) |
| ACK | `0x22` | `nonce(16) + status(1) + pin(1) + level(1)` + MAC(32) |

- 仍在协议版本 1；新类型是增量，旧固件会静默忽略（不会误动作）。
- 板端只接受 `GPIO_13` / `GPIO_10`；nonce 复用 SFC1 的已用窗口（落 NV），重复帧回 `REPLAY`。
- 板端执行后在 OLED 显示 `WS63 DEVICE / IOxx = ON|OFF`。

## 3. 主机侧

- `src/device-actuator.cjs`：`createSerialActuator({portPath, key})` → `actuate({device, op})`；
  串口 115200，等 ACK 默认 3 秒；未映射的 op **直接拒绝**（`ACTUATOR_MAP`），不乱动 GPIO。
- 映射：`unlock/open/on → IO13 高`、`lock/close/off → IO13 低`、`beep/alarm → IO10 高`、`silence/mute → IO10 低`。
- 控制台：`protocolAction === 4` 时调用执行器；成功记 `actuated/pin/level`，失败抛 `MailerError('unknown')`。
- 配置：`SAFE_OFFICE_ACTUATOR_PORT`（默认跟随 `SAFE_OFFICE_NEARFIELD_PORT`）；都没配 = 只记录不驱动。
- 设备页在有执行器时显示「设备联动：真实 GPIO…」。

## 4. 烧录与配网（本轮踩坑记录）

1. **`--only-burn ws63-liteos-app-sign.bin` 没有生效**：烧录显示成功，但板子仍跑旧/出厂镜像（串口周期 `at_recv` 日志，挑战无响应）。
2. **全量烧录**：921600 连续两次在 1.18% / 7.11% 断（`Send download flash image command failed`）；**降到 460800 一次成功**。
3. 全量烧录会写 NV → **配网钥匙被清**；板端 OLED 显示 `WS63 PROVISION / PAIR CODE / XXXXXXXX`，
   用 `node scripts/provision-device.cjs --port COM11 --code <8位码> --label ws63-A` 重新配网。
4. 配网后 `device_id` 仍为 `1d889565919dce48`（按 label 派生）。

## 5. 验证（2026-11-04）

- 执行帧直发：`npm run actuator:probe -- --port COM11 --pin 13 --level 1` → ACK `status=0`；
  用户现场确认 **LED 亮**；`level 0` 熄灭；`--pin 10 --level 1` 蜂鸣器响、`0` 停。
- 控制台真实路径（`ConsoleService` + 真执行器）：`unlock` → `actuated=true pin=13 level=1`，
  0.9 秒后 `lock` → `level=0`，审计「设备执行 ×2」。
- 单测：执行帧往返/MAC、映射、ACK、超时；控制台 stub 执行与失败转 unknown。
- 全量：**582 项（580 通过 + 2 跳过）+ 11 E2E**。

## 6. 边界（写进材料）

- 只证明「板子按确认结果执行了 GPIO」；**不证明真实门锁/继电器动作**（当前硬件没有继电器/锁体）。
  2026-11-05 起固件/主机已支持 IO12 继电器（[68](68-继电器与锁体支持-2026-11-05.md)），
  默认关闭；接上继电器与锁体后仍需门磁/锁状态反馈才能证明「门真的开了」。
- 串口与确认共用：确认挑战占用串口时执行会失败（报 unknown，不重试）。
- 未映射的 device/op 一律拒绝执行；执行器不猜语义。
- nonce 窗口防重放；但物理按键/断电视为本地操作，不在本协议防护范围。

## 7. v0.52.1 复核修复（2026-11-04）

评审指出两处问题，均已修复并重新烧录验证：

1. **执行回执未绑定本次命令**
   - ACK 载荷从 `status+pin+level` 改为 **`nonce(16)+status+pin+level`**（19B + MAC）；
     板端把执行帧的 nonce 原样回带。
   - 主机先按 `timingSafeEqual(nonce)` 绑定本次命令，**旧回执/其他动作的 ACK 一律忽略**（继续等，直到超时）；
     nonce 对上但 `pin/level` 不符视为协议异常，直接失败（`ACTUATOR_ACK_MISMATCH`）。
2. **serialport 缺失时错误处理无效**
   - 先判依赖是否存在再构造端口；缺失返回 `ACTUATOR_NO_SERIALPORT`（“serialport 未安装”），
     不再是 `new null` 的 TypeError。
   - 测试注入 `serialPortModule: null` 覆盖该分支。

重新验证（真机）：

- 460800 全量烧录成功 → 配对码 `57a63a38` → 重新配网（`device_id` 不变）
- `actuator:probe` 点灯/灭灯：ACK `status=0, pin=13, level=1/0`，nonce 匹配通过
- 控制台路径（`ConsoleService` + 真执行器）：`unlock/lock` 均 `actuated=true`，审计两条
- 复跑：**578 项测试（576 通过 + 2 跳过）+ 11 E2E 全绿**

> 兼容性：ACK 载荷格式变更，**板端固件与主机必须成对升级**（同协议版本 1，无旧版兼容）。

## 8. v0.52.2 第二轮复核修复（2026-11-04）

1. **高：确认与执行争用同一串口**
   - 执行前先 `nearfieldTransportFactory.close()` 并清空 `_nearfieldTransport`，执行器独占端口；
     下一次发起挑战时工厂懒重连。
   - 单测钉住顺序：`close-transport → actuate`，且执行后 `_nearfieldTransport` 为 null。
2. **高：取消可能变成批准执行**
   - 真板路径收到回执后，若请求为 `cancel`，直接消费 nonce、操作置 `rejected`、
     写「取消优先于板端决定」审计，不进入 `_completeChallenge`（板端批准也不执行）。
3. **中：共享启动失败后仍采集屏幕**
   - 前端 catch 分支停止已获取的轨道、清空 `srcObject`、恢复按钮状态（停止按钮回到禁用）。
4. **中：可结束他人的共享会话**
   - `stopScreenShare` 核对 owner；非本人且非管理员/审计员返回 403，并写「屏幕共享越权停止」审计。

验证：**582 项测试（580 通过 + 2 跳过）+ 11 E2E**。真板回归（修复前/后）：修复前复现
`Opening COM11: Access denied`（`outcome=approved-but-unknown`）；修复后同一路径
`outcome=approved`、`state=executed`、`actuated=true pin=13 level=1`（LED 亮），随后 `level 0` 熄灭。
