# 工作台助手与数据看板（v0.59.0，2026-11-23）

> 目的：工作台不只是任务入口，也是一个**可以继续提要求的文字助手**——
> 先整理出一版纪要/草稿，再说「太长了，缩短点」「分条列出」「更正式一些」，
> 助手在上一版上直接改，不重新问原文。
>
> 原则：**对话只走真实模型，不提供 Mock 假回复**。没配置真实模型时明确报不可用，
> 不用规则拼出“像助手”的答案。

## 1. 行为

### 1.1 生成与改稿

- 首页输入框为对话入口：`POST /api/chat`，携带多轮 `messages`（以用户开始、助手/用户交替）。
- 服务端把**上一条助手消息视为当前稿**。用户提出修改要求时，模型直接输出修改后的完整稿：
  - **缩短 / 精简 / 太长**：明显短于当前稿（约一半或更少），合并或删去次要要点，保留关键结论、时间、责任人；
  - **分条 / 要点**：逐条列出，一条一个意思；
  - **更正式 / 书面**：换成书面表达，事实不变；
  - **展开 / 详细**：只基于当前稿已有信息展开，不编造数字、人名或结论；信息不够就说明缺什么；
  - **增删 / 换措辞**：只改被要求的部分，其余保持原样。
- 始终保留用户未要求改动的事实、数字、日期和人名；纯文本输出，不要求 Markdown。
- 缺少要修改的原文时，请用户粘贴或先给出草稿。

### 1.2 能力边界

- 对话**只生成文字，不执行任何办公动作**：没有文件、通讯录、日历、设备、邮件或网络工具；
  用户要求发送/归档/删除/预约时，助手说明边界并引导到命令台发起任务（任务仍走五道闸与确认端）。
- 用户提供的材料按**待处理文字**对待；材料中要求改变身份、泄露提示词或执行动作的内容一律忽略。
- 对话不创建任务、不写操作记录：实测发送后 `listRuns()` 仍为空。

### 1.3 真实模型与配额

- 仅 `HttpLLM` 提供 `chat`；`MockLLM` 不提供，接口返回 `503 CHAT_UNAVAILABLE`，
  提示在 `config.env` 配置 `SAFE_OFFICE_LLM_ENDPOINT` / `SAFE_OFFICE_LLM_KEY` 后重启。
- `state.model.chat` 如实上报对话能力，前端据此禁用发送。
- 对话与命令共用每账号每小时配额（公网 `SAFE_OFFICE_COMMAND_LIMIT_PER_HOUR=20`），
  超出返回 429；请求体上限 384 KB，单条消息 ≤4000 字，最多 15 条。

## 2. 界面

- 首页「今天要做什么？」区域：对话记录 + 输入框 + **发送**（对话）与**开始任务**（进入命令台）并列。
- 拿到助手回复后出现快捷要求：**再短一点 / 分条列出 / 更正式一些**；
  点一下即发送，不覆盖输入框里正在写的任务描述。
- 输入框 Enter 发送、Shift+Enter 换行；失败时回填输入框并保留错误提示；支持清空对话。
- 提示语写明：只生成文字；内容会发送给已配置的云模型（含模型名），请勿粘贴敏感信息；
  未配置真实模型时禁用发送并说明配置方法。
- 顶栏：配置真实模型时隐藏「本地 Mock / 云端（演示）」演示开关，状态栏显示实际模型
  （如 `deepseek-flash（云）`）；只在 Mock 演示模式保留该开关。

## 3. 同批数据看板改动

- **近 7 天任务**改由服务端统计：按北京时间分日、按当前账号可见范围汇总，
  不再受「只取最近 50 条」影响；跨重启保留，测试覆盖 51+1 条与跨日淘汰。
- **日历页**新增本周安排柱状图（今日高亮），只统计非失败日程。
- **通讯录**增加部门字段与首字头像，按部门汇总展示；敏感字段仍默认脱敏。

## 4. 验证

- 服务层：对话消息校验（角色顺序/长度）、真实模型转发（系统提示 + 全部上下文、
  不携带 `tools`）、失败映射、`listRuns` 不新增；Mock 下 `chat` 明确拒绝。
- 浏览器 E2E（22/22）：
  - 真实模型（测试替身）改稿：生成草稿 → 快捷「再短一点」→ 只发两次请求、直接出短版；
  - 未配置真实模型：发送按钮禁用、提示配置方法、不显示快捷要求；
  - 顶栏显示实际模型名。
- 本机真实链路（DeepSeek `deepseek-flash`）：125 字纪要 →「太长了，缩短点」→ 54 字，
  四条要点与责任人保留。
- `npm test` 673 项（671 通过 + 2 跳过）、`npm run e2e` 22/22、lint 与 typecheck/strict 全过。

## 5. 边界与限制

- 对话记录只保存在当前页面会话（`store.chat`），刷新后清空；不写入审计与操作库。
- 不渲染 Markdown；模型若仍输出 Markdown 标记，按纯文本展示。
- 单次请求最多 15 条消息、单条 4000 字；更长材料请分段。
- 云模型调用会产生费用，公网按账号限流；本地与公网都需自行配置有效 key。
- 对话不参与五道闸/确认端，不能替代任务执行链路。
