# 生成超时后的中止反馈（v0.55.1，2026-11-21）

> 目的：生成阶段模型超时后，任务不再显示成“完成”或只剩一条裸错误；
> 页面明确标「已中止」，给出**失败阶段/类别**，并保留**已完成的步骤**；
> 刷新后仍能恢复同一失败信息。

## 1. 行为

### 1.1 执行阶段显示真实动作

- 运行时 `onStage('执行', { step, total, action })` 带上当前工具名。
- 前端阶段文案由 `toolLabel(action)` 渲染：**读取资料 1/3 → 生成摘要 2/3 → 发内网邮件 3/3**。
- 进度只显示实际执行到的步骤；后续步骤不伪造。

### 1.2 超时 → 已中止

- 运行时捕获生成阶段模型故障（如 `TimeoutError`），写「任务中止」审计：
  `{ class, reason, atStep, action, notExecuted }`，随后 `settle('aborted')`。
- 控制台任务状态：
  - 规划失败 → `stage='已中止'`，`failure.phase='规划'`
  - 执行/生成失败 → `stage='已中止'`；`action='summarize'` 时 `failure.phase='生成纪要'`，
    否则 `failure.phase='执行'`
  - `failure.category` 取故障分类（如「模型超时」）
- 前端显示 block 提示：**「生成纪要阶段中止（模型超时）。后续步骤未执行。请先查看步骤记录，再决定是否重试。」**

### 1.3 刷新恢复

- `failure` 由本次运行的审计切片（`规划失败` / `任务中止`）计算，写入 run 结果；
  `getRun` 对已完成运行从 `runs` 记录返回，刷新后 `stage='已中止'` 与 `failure` 保持一致。
- 已执行步骤（如 `readDoc(M2) ✓`）保留在 `result.lines`；未创建的邮件操作不补造。

## 2. 回归验证

新增服务层测试：**「纪要生成超时：显示中止阶段，保留读取记录且不创建邮件操作」**

- 假 LLM：`plan` 返回 readDoc → summarize → sendInternalEmail；`generate` 抛 TimeoutError。
- 断言：
  - `stageLog` 含 `action='summarize'`；
  - `stage='已中止'`；
  - `failure={ phase:'生成纪要', category:'模型超时' }`；
  - `lines` 保留 `readDoc(M2) ✓`；
  - `operations=[]`（超时后没有创建邮件操作）；
  - 删除 liveRun 后重新 `getRun`，`stage` 与 `failure` 不变。

`npm run ci` 全绿：**655 通过 + 2 跳过、E2E 20/20**，lint/typecheck/strict 全过。

## 3. 边界

- 只对模型故障（`classifyModelFault`）归类为「中止」；网关拒绝/策略拒绝仍走原「拦截/拒绝」路径。
- 「已中止」表示本任务停止，不代表已执行的副作用可回滚；步骤记录与操作状态仍以审计为准。
- 生成阶段真实模型尾延迟没有变化；v4.1 正常集 P95 90.6s 仍待优化，整体 P95 需在下一轮全量复测。
- 刷新恢复依赖 run 记录/审计切片；超过保留上限的旧 run 不在列表时无法恢复（与既有任务列表一致）。
