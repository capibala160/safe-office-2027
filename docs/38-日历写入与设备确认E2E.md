# 日历 .ics 真写入 + 设备确认 E2E（v0.37）

> 两件收尾事：① `scheduleMeeting` 一直只输出一句"已预约"，是模拟动作里最容易被问的一项；
> ② E2E 覆盖了手机确认，却没覆盖**虚拟 WS63 设备确认**这条主线路径。

## 1. 日历 .ics 真写入

**适配器（`src/calendar-adapter.cjs`，零依赖）**

- 生成标准 `VCALENDAR / VEVENT`：`UID`、`DTSTAMP`、`DTSTART`、`DTEND`（默认 1 小时）、`SUMMARY`、`DESCRIPTION`。
- 文本按 RFC 5545 转义（`\`、`;`、`,`、换行）。
- 时间支持 ISO 与 `YYYY-MM-DD HH:mm`，统一转 UTC（`...Z`）；无法解析直接报错，不猜。
- 文件名 `meeting-<sha256(title|at|id) 前 12 位>.ics`：同一会议重复执行覆盖同一文件，不产生副本。
- `writeMeeting` 未给目录 → 返回 `simulated`，不冒充写入。

**接入**

- `ConsoleService` 新增 `calendarDir`（默认读 `SAFE_OFFICE_CALENDAR_DIR`），未配置时 `calendarWriter=null`，行为与 v0.36 一致。
- `AgentRuntime` 的 `scheduleMeeting` 执行分支改为 `await calendarWriter(...)`：
  成功 → 效果串带真实路径 + 审计 `日历写入`（含 file/uid）；
  失败 → 风险 +10、审计 `执行失败`、效果明确写"未伪造成功"；
  未配置 → 效果标注"模拟"。
- 日历页：Agent 预约现在标 **已落盘 / 模拟**，已落盘显示文件路径。

**配置**

```ini
SAFE_OFFICE_CALENDAR_DIR=C:/Users/you/safe-office-calendar
```

## 2. 设备确认路径 E2E

新增第 7 条 E2E（`e2e/ui.e2e.cjs`）：

1. 员工登录 → 工作台外发样例 → 冻结操作；
2. 员工在设备页选中该操作 → 「发起挑战」（ROLE_APPROVE）；
3. 退出，换**设备助手**登录 → 设备页出现 OLED 挑战 → 点「确认」；
4. 断言：操作 `executed`、outbox `sent`、审批页显示"已执行"。

换人一步是刻意设计——v0.31 的四眼原则禁止登录用户批准自己发起的操作，
设备助手（ROLE_DEVICE）与发起人不同，才能真正走通虚拟设备确认。

## 4. 边界

- `.ics` 只证明**文件已落盘**，没有导入任何日历账户、没有邀请参会人、没有同步。
- 时区按本机解释后转 UTC；跨时区会议的原始时区不会保留（`TZID` 未做）。
- 重复预约会覆盖同名文件；修改会议时间是另一个文件名（哈希含时间）。
- 设备确认仍是**虚拟设备**（真实 SFC1 帧与 HMAC），不是 WS63 硬件；硬件路径仍待插板。
- 日历目录是本地路径，换机/重装需重新配置；不随仓库走。
