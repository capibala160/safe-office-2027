# 读取面权限、角色锁定与 validation 复跑（v0.30）

> 接 v0.29 复查建议，继续收口两处：
> 1. 访客仍可读审计/报告/操作/文档；2. 登录角色与顶栏下拉不一致。
> 同时用当前代码复跑 validation 真实评测。

## 1. 读取面角色权限

在 v0.29 的接口权限基础上补齐：

| 接口 | 允许角色 |
|---|---|
| `/api/documents`、`/api/documents/:id` | 员工、管理员、审计员 |
| `/api/emails`、`/api/outbox/:id/reconcile` | 员工、管理员、审计员 |
| `/api/calendar`、`/api/contacts` | 员工、管理员、审计员 |
| `/api/operations`（列表）、`/api/operations/:id`（详情） | 员工、管理员、审计员 |
| `/api/governance`（治理概览） | 员工、管理员、审计员 |
| `/api/audit`（完整审计） | **管理员、审计员** |
| `/api/report`（治理报告） | **管理员、审计员** |

- 访客 / 设备助手只能读状态与设备相关接口
- 未启用登录（无用户表）时保持旧行为
- 测试：访客读 audit/report/operations/documents 全 403；员工读 operations 200、audit 403；
  审计员读 audit/report 200

## 2. 登录角色锁定

- `/api/bootstrap` 与 `/api/state` 返回 `authUser: {username, role}`
- 前端 `renderRoleOptions` 登录后：
  - 把 `store.role` 设为会话角色
  - 下拉框 `disabled`，title 说明“已登录为 X，角色已锁定”
- 避免用户在下拉里选管理员后被服务端 403
- E2E 断言：登录后 `#role-select` 禁用且值为「员工」
