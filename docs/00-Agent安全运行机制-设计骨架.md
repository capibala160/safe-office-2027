## 0. 一页速览

**一句话**：围绕办公智能体的"运行"与"数据处理"，建一套四层机制——**运行时（L1）→ 安全网关（L2，五道闸+工具沙箱）→ 治理中心（L3，含可视化）**，外加**物理锚点（L4 星闪近场确认）**；模型侧**端云协同但机密不进云**。让每个危险动作都有闸门、每次放行都有凭据、每步执行都可回溯、每次数据流动都可审计。

```
用户(办公人员)
   │ ① 下指令
   ▼
┌──────────────────────────────────────────────────────┐
│ L1 Agent 运行时（自建，ArkTS）                          │
│   意图解析 → 任务计划 → 工具调用循环                     │
└──────────────────────┬───────────────────────────────┘
                       │ ② 每一步（含工具调用）过闸
┌──────────────────────▼───────────────────────────────┐
│ L2 安全网关（核心创新层）：五道闸 + 工具沙箱              │
│   闸1 输入消毒：文本/语音/图片 三通道 · 注入整句隔离       │
│   闸2 权限令牌：工具白名单 × 最小权限（任务签发 · TTL）    │
│   闸3 数据边界：文档密级 / 脱敏 / 外发拦截                │
│   闸4 执行管控：高危二次确认 + 执行前快照可回滚            │
│   闸5 输出检测：机密碎片比对 / 不合规话术 / PII 兜底       │
│   ＋沙箱：执行环境独立一锁（文件作用域/网络通道/物理世界）  │
└──────────────────────┬───────────────────────────────┘
       ③ 全线日志 ▏     │ ④ 高危放行需物理确认
┌──────────────────────▼──────┐   ┌──────────────────┐
│ L3 治理中心                  │   │ L4 物理锚点        │
│   策略中心(角色×场景×动作,热更新)│◀──│  WS63 星闪节点     │
│   审计日志(哈希链 + HUKS 签名)  │   │  SLE 近场握手      │
│   风险计量(拦截事件+行为因子)    │   │  = 配对设备主动确认（规划）    │
│   治理面板(可视化) ← 报告/端侧   │   └──────────────────┘
└─────────────────────────────┘
        ▲
  模型边界（端云协同）：进模型前消毒 · 机密正文不进云 · 出模型先校验
```

## 2. 演示场景设定【已定】

**主线场景（2026-10-14 拍板）：会议纪要线 · 办公文档 Agent「小办」**
1. 用户："把昨天的评审会纪要整理成正式版，发到部门内网归档"
2. Agent：读纪要 + 外部参会方材料（工具）→ 整理正式版（数据处理）→ 对外同步（高危：外发）→ 归档（写）

**为什么选它**：① 覆盖"运行 + 数据处理"全链路；② 外部来料天然是注入点、对外同步天然是高危动作；③ 与"文档审查"类项目距离最远，原创叙事干净；④ 素材简单，评委秒懂。图片/语音/设备联动等能力以支线幕补充展示。

## 4. 机制架构·详述

### 4.1 L1 Agent 运行时（自建，ArkTS）
- 意图 → 计划（DAG 步骤）→ 逐步执行 → 每步**过闸+过沙箱后才允许调用工具**
- 规划器=**可插拔 LLM**（原型已实现 MockLLM 离线演示 / HttpLLM 真实接入骨架）；**不信任模型输出**：进模型前上下文先过闸1（`<DOC>` 数据块隔离），出模型后过**计划校验**（结构+必需参数+**来源溯源**：外发收件人/上传地址只能来自用户指令，来自外部材料的一律移除），执行再走五道闸+沙箱；护栏与模型完全解耦
- **模型边界（A3）**：规划/生成调用模型时按文档密级分流——本地模型可收全量，云侧模型只收非机密正文，机密以占位符替代；本次分流（送入/分流清单）写入审计"数据流向"

### 4.2 L2 安全网关（核心创新层：五道闸 + 沙箱）
- **闸1 输入消毒**：外部内容（文档/邮件/网页/录音转写/图片识别）与指令分离；模式库覆盖：指令覆盖、数据搬运、隐蔽指令、提权诱导、伪造系统指令、绕过审批、伪造授权、非法获取客户信息（中英双语）；命中句整句隔离，一句话多模式全报
- **闸2 权限令牌**：任务级"能力令牌"（工具白名单、外发域名白名单、次数上限、**TTL 有效期**）；被拒调用不耗配额；超范围拒绝并告警
- **闸3 数据边界**：文档密级（公开/内部/机密）；机密禁出站（含内网邮件）；外发自动脱敏（手机号/邮箱）；上传外部仅公开级
- **闸4 执行管控**：高危清单（外发/删除/打印/共享/设备联动/上传）→ 二次确认；确认凭据=**星闪近场**（上板）/演示版模拟；执行前落快照，一键回滚
- **闸5 输出检测**：生成物与外发内容出门前比对——机密原文片段（防"总结式泄密"）/违规承诺话术/制度规避/诱导隐瞒；PII 残留自动兜底脱敏
- **工具沙箱【v0.3 强化】**：执行环境层的独立一锁——每个工具显式声明所需资源（文件作用域/网络通道/物理世界），**令牌管"这个任务能不能"，沙箱管"这个环境允不允许"**；路径逃逸（`../`）检出即拒；无档案工具一律 fail-closed；上板对应 OH 应用沙箱+权限模型

### 4.3 L3 治理中心
- **策略中心**：矩阵（角色 × 场景 × 动作 → 允许/确认/禁止）；**策略热更新**（不重启生效，变更留痕入审计）；未声明=默认拒绝（fail-closed）
- **审计日志**：链式（前条哈希进后条）+ HUKS 签名防篡改；字段=序号/类型/详情/时间戳/前哈希；覆盖：指令→上下文→数据流向→计划→校验→逐闸→执行→快照/回滚；演示含篡改检测
- **风险计量**：**拦截事件**（各闸拒绝按权重计分）+ **行为因子**（高频/异常时段/持续越权，可解释、可复现）；超阈值**自动冻结高危通道**（近场确认亦不放行）→ 人工复核：clear 解冻清零 / escalate 保持冻结；详见 §7
- **治理面板（可视化·B4/A2）**：原型期=治理报告（单文件 HTML：概览卡/风险明细/复核记录/各闸时延/审计时间线/链校验状态）；P2=ArkTS 端侧面板（同一数据模型）

### 4.4 数据流向与部署视图（A3 应答）

```
┌─────────────── 主设备（OH 6.0.0.1 标准系统 · 端侧）───────────────┐
│  L1 运行时 ── L2 网关(五闸+沙箱) ── L3 治理(策略/审计/风险/面板)    │
│      │             │                                            │
│      │      ┌──────▼──────┐   安全策略 100% 在端侧（云侧零信任）    │
│      │      │  模型边界    │                                     │
│      │      └──┬───────┬──┘                                     │
│      │   本地模型    云侧模型(仅非机密正文+已消毒上下文)              │
│      │   (全量)        │                                        │
│      ▼                ▼                                        │
│  工具执行(本地工具/系统接口/第三方服务) ← 沙箱约束                 │
└──────────────┬─────────────────────────────────────────────────┘
               │ SLE 近场（高危放行凭据）
        ┌──────▼──────┐
        │ WS63 星闪节点 │← 员工手机/工牌（轻量系统 · SDK 基线 5.1.0）
        └─────────────┘
```

**数据流五段（每段的安全动作）**：①外界内容→知识库（闸1 消毒隔离）→ ②知识库→模型（**分级分流：机密不进云**）→ ③模型→计划（计划校验+溯源）→ ④计划→执行→出站（五闸+沙箱全过）→ ⑤全程→审计链（哈希链+HUKS 签名）。
**隐私保护方案**：机密不出域（云模型不豁免）；PII 强制脱敏（查询最小暴露、外发兜底）；通讯录/批量导出能力"目录外用不提供"；数据流向全程留痕可审计。

### 4.5 L4 物理锚点（WS63 星闪）
- 场景：闸4 放行高危操作时 → 主设备发起 SLE 近场握手 → 员工手机/工牌节点在近场应答（按键确认）→ 放行
- 意义：**将已配对设备持有者的主动确认绑定到具体操作**——防远程冒充、防 Agent 被挟持后偷跑
- 协议草案：§8

### 4.6 安全可视化（B4 / A2）
- 原型期：`node demo.cjs` 末尾自动生成 `out/governance-report.html`（零依赖单文件；浏览器直开/可打印）
- P2：ArkTS 端侧治理面板（同一数据模型）；可加"历史会话检索/策略编辑"交互
- 演示价值：答辩现场一页报告=整场攻防的证据链（谁放行、拦了什么、风险多高、花了几毫秒）

## 7. 风险评分模型（可解释 · 原型 v0.5 实装）

**总分 = 拦截事件（客观阻力点）+ 行为因子（行为特征）**

| 因子 | 权重 | 数据源 | 说明 |
|---|---|---|---|
| 计划校验拦截 | +25/次 | 规划层 | 非法动作/来源溯源命中 |
| 闸2 令牌拒绝 | +15/次 | 网关 | 越权工具/域名/次数/TTL |
| 策略拒绝 | +30/次 | 治理层 | 角色×动作禁止 |
| 沙箱拒绝【v0.3】 | +20/次 | 执行环境 | 资源越界/环境未授权 |
| 闸3 数据边界拦截 | +25/次 | 网关 | 机密出站等 |
| 闸5 输出拦截 | +20/次 | 网关 | 机密碎片/不合规话术 |
| 闸4 未确认 | +10/次 | 网关 | 超时/拒近场 |
| 输入消毒命中 | +25/次 | 网关 | 注入隔离 |
| 行为因子·高频 | +8 | 运行时观测 | 10 分钟窗口内高危动作达 3 的整数倍 |
| 行为因子·异常时段 | +6 | 运行时观测 | 00:00–06:00 执行高危动作（每小时内一次） |
| 行为因子·持续越权 | +10 | 运行时观测 | 同一动作 10 分钟内被拦 3 次 |

**处置流**：分数 ≥ 阈值（原型 60）→ **自动冻结高危通道** → 人工复核 → clear（解冻清零，观测窗口一并清零）/ escalate（保持冻结，升级处置）。
**权重口径**：当前为原型初值（量级反映危害度排序）；P1 依据演练数据与业务口径调参——**答辩叙述按"可解释、可审计、可调参"讲，不吹"最优模型"**。

## 8. 星闪近场确认协议 v0.1（草案 · P2 细化实装）

- **角色**：主设备（发起挑战）=OH 标准系统；员工节点（应答者）=WS63 工牌/手机
- **流程**：① 高危操作待确认 → ② 主设备发起 SLE 近场连接，发送**挑战**（操作摘要 hash + 一次性随机数 nonce + 时效） → ③ 员工按键确认后回复 **MAC = HMAC(会话密钥, 操作摘要‖nonce‖时间戳)** → ④ 主设备验算放行，凭据入审计 ⑤ 超时（默认 30s）/远离即拒绝
- **防重放**：nonce 一次性 + 时效窗口
- **中继边界**：SLE 连通不能证明距离，当前不保证防中继；**操作摘要绑定**（本次确认只对"这一个操作"有效，不是"批准一切"）
- **在场语义**：按键=主动确认（防"人到了但不知情"）
- **P2 待细化**：配对流程与密钥更新、按键交互形态（工牌按键/手机弹窗）、多人多节点时的目标选择

## 10. 办公能力分级表（命题点名 8 类 + 3 类扩展）

**风险级定义**（L1 最宽 → L4 最严）：

**纪律**：未在策略矩阵声明的「角色 × 动作」= 默认拒绝（fail-closed）。

| # | 能力（命题点名） | 级 | 承载工具 | 调用约束 |
|---|---|---|---|---|
| 1 | 邮件发送 | L3 | sendInternalEmail / sendExternalEmail | 内网=常规；外发=域名白名单 + 密级/脱敏（闸3）+ 近场确认（闸4）+ 输出检测（闸5）+ 沙箱网络通道；不得代发他人身份（无委托令牌默认拒绝） |
| 2 | 文件访问 | L2 | readDoc / deleteDoc | 读取按密级+沙箱作用域；删除=不可逆：二次确认 + 快照可回滚 + 令牌次数上限；`../` 路径逃逸由沙箱拒绝 |
| 3 | 会议预约 | L2 | scheduleMeeting | 令牌内自动；预约外部参会人升级确认（规划中） |
| 4 | 通讯录读取 | L3 | readContact | 仅单条按名查询；结果默认脱敏（最小暴露）；批量/导出能力不提供（目录外动作一律移除） |
| 5 | 打印控制 | L2 | printDoc | 公开=放行；内部=二次确认 + 水印与操作人标识；机密=禁止打印 |
| 6 | 录音转写 | L2 | transcribeAudio | 转写结果=外部内容：强制过闸1（注入隔离）再入知识库 |

### 10.1 Agent 角色分级（v0.9）

Agent 不是"匿名调用方"：每个 Agent 启动时带一份受信任清单（agentId / role / allowedTools / documentScopes / modelLocation），运行时校验清单摘要与角色边界；任务令牌 = **角色允许 ∩ 清单申请 ∩ 任务需要**（任何一层不给就不给）。

| 角色 | 可读密级 | 工具面 | 外部域名 | 备注 |
|---|---|---|---|---|
| 员工 | 公开/内部/机密 | 除 uploadToCloud 外全部 | 按任务签发 | 标准办公 |
| 实习生 | 公开/内部 | 只读（读取/识别/转写/摘要/通讯录） | 无 | 不得发送/预约/写入/物理动作 |
| 审计员 | 公开/内部/机密 | 只读 | 无 | 看审计与文档，不执行业务 |
| 设备助手 | — | 仅 deviceControl | 无 | 物理动作仍需确认 + 近场 + 沙箱 |
| 管理员 | — | 无业务工具 | 无 | 只做策略管理（不在业务链路） |
| 访客 | — | 无 | 无 | 无任何业务权限 |

**委托**：代发/转授权必须持委托令牌（from / to / actions / expiry / MAC）；令牌只证明"调用方持有"，不证明委托人真实身份；目标仍须在用户指令中可溯源。
**边界**：清单摘要为进程内防篡改摘要，不是密码学签名；上板后由受信任配置/HUKS 签名。管理员身份仍由调用方保证，未实现登录。

## 13. 创新点提炼（答辩用）

1. **护栏在模型之外**：不信任模型输出的分层兜底（消毒→校验→五闸→沙箱），且用"故意被带偏的 Mock 模型"把兜底层永远置于被测试状态
2. **权限治理可操作化**：办公能力分级表=单一事实源，工具目录/令牌/策略/沙箱/模拟攻击全部由它派生——"治理"不是 PPT 是数据
3. **物理锚点**：星闪近场将已配对设备持有者的主动确认绑定到具体操作（防远程冒充/防 Agent 挟持偷跑），且与操作摘要绑定（防"批准一切"）
4. **数据流向可审计的端云协同**：机密正文不进云 + 每次分流留痕——把"AI 数据出域"这个行业痛点变成一条可展示的审计记录
5. **治理闭环与可回滚**：风险冻结→人工复核→解冻/升级的闭环 + 高危操作快照回滚——安全的"后果管理"（不仅拦住，还能挽回）
