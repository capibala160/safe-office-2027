# 任务工作台与任务内确认（v0.54.0 · 2026-11-19）

> 依据一轮控制台设计评审，先落地三项影响最大的改动：
> **首页改成任务工作台、命令台默认隐藏高级参数、确认过程保留在当前任务**。
> 目标是让第一次打开的人先看到「要完成什么」和「哪些事等我确认」，
> 而不是先学习工具、沙箱、闸门和哈希。
>
> 范围：只改控制台前端（`public/`）与 E2E，不动五道闸、确认协议、审计和服务端权限；
> 版本 **v0.54.0**。

## 1. 工作台：从「功能目录」改成「任务入口」

| 改动 | 说明 |
|---|---|
| 主操作区 | 首屏只保留一个任务输入框 + 「开始任务」；输入内容带到命令台，不要求先理解工具 |
| 快捷填入 | 「整理会议纪要 / 外发邮件确认 / 门锁控制」三个演示常用任务，一键填入 |
| 待你处理 | 直接读 `GET /api/operations?state=frozen`，最多列 4 条，可就地「现在确认」或看详情 |
| 最近任务 | 读 `GET /api/commands`（最近 5 条），显示指令、动作数、风险分，可去回放 |
| 状态收敛 | 风险/审计只在右侧栏和顶部保留一处；首页不再堆四张统计卡和重复事件列表 |
| 演示分离 | 原首页的「演示剧本 / 一键样例 / 演示前自检 / 最近事件」移到新页面 **演示场景（#/demo）**，侧栏「演示」分组进入 |

边界：工作台不改变服务端授权，只是把已有能力按任务顺序摆出来。

## 2. 命令台：默认只留「描述任务、选择资料、看建议」

- 默认可见：任务描述、选择资料、附件、**建议权限**、执行；
- 工具、外发域名、调用次数、执行范围收进 **高级设置**（原生 `<details>`，默认折叠）；
- 「建议权限」由前端关键词规则给出（整理→读取+摘要；外发→读取+对外邮件；门锁→设备控制等），
  点「按建议勾选」才写入工具复选框；**它只是提示，服务端策略仍是最终授权**；
- 工具名改为中文可读标签（`readDoc` → 读取资料），保留等级；
- 页面副标题去掉「五道闸」等实现词。

## 3. 任务内确认抽屉

`bindOpActions` 的「发起确认」不再一律跳设备页：

- 默认在**当前页面右侧打开抽屉**，展示动作、目标、密级、剩余时间、内容摘要、完整正文（可展开）、附件名和 operationHash；
- 抽屉内直接「批准并执行 / 拒绝」，结果显示在抽屉内；关闭后刷新当前页；
- **角色边界不变（四眼原则）**：
  - 发起确认：`员工` / `管理员`（服务端 `ROLE_APPROVE`）；
  - 虚拟设备批准：`设备助手` / `管理员`（服务端 `ROLE_DEVICE`）；
  - 员工发起后看到「等待设备助手批准」，不显示批准按钮；
- 设备助手打开同一条操作时，会先复用**已存在的待确认挑战**（`GET /api/device` 的 `pending`），
  不会重复发起（避免 409「已有待确认任务」）；
- 已接真板（串口）或关闭虚拟确认时，仍走原设备页/手机确认端路径。

## 4. 文案校准

- 页脚「录音转写仍模拟」改为「录音转写按凭据配置真实/模拟」——v0.51 起配置腾讯云密钥后可真实转写；
- 顶栏「近场（内置闸4）」改为「近场确认」，技术说明留在 tooltip；
- 「仅本机」「仅监听 127.0.0.1」改为「默认仅本机监听」，与实际可反代部署一致。

## 5. 验证

| 项 | 结果 |
|---|---|
| 单测 | **633 项（631 通过 + 2 跳过）**，全绿 |
| 浏览器 E2E | **13/13**，其中设备确认用例改为「员工发起 → 设备助手在工作台抽屉批准 → 已执行」 |
| 静态检查 | `npm run lint`、`npm run typecheck`、`npm run typecheck:strict` 全绿 |
| 手工检查 | 1440px 工作台/命令台/抽屉、390px 工作台截图检查；无横向溢出 |

新增/修改的 E2E 断言：

- 工作台存在任务输入，快捷填入可用；
- 演示场景页仍可跑一键样例；
- 员工发起确认后抽屉无「批准并执行」按钮，提示需要设备助手；
- 设备助手在抽屉批准后，操作状态 `executed`、outbox `sent`。
