# strict typing 全仓收尾（2026-11-05）

> 本轮把 [47-软件剩余清单](47-软件剩余清单.md) §5 与 [62-完成度盘点](62-完成度盘点-2026-11-04.md) §6
> 的最后一项非硬件欠账做完：`console-service` / `server` / `auth` / `mailer` 纳入 `typecheck:strict`。
> 由于 `tsc` 会沿 import 检查整个依赖图，实际覆盖从 11 个模块扩到 **50 个源文件**
> （控制台 + 服务端 + 全部被其引用的业务模块）。
> **1655 个类型错误 → 0**；运行时行为不变，测试口径不变。
> 起点 HEAD `92a041e`（v0.52.2），本轮为纯类型收尾，不 bump 版本号。

## 1. 范围

`tsconfig.strict.json` 的 include 新增：

| 文件 | 角色 |
|---|---|
| `src/console-service.cjs` | 控制台服务门面（3937 行，原 693 个错误） |
| `src/auth.cjs` | 登录 / 多用户 / TOTP |
| `src/mailer.cjs` | 邮件适配器基类与 Fake/HTTP 实现 |
| `server.cjs` | HTTP 服务端（1366 行，原 135 个错误） |
| `types/nodemailer.d.ts` | 可选依赖的最小模块声明（见 §3.4） |

`tsc` 顺带纳入 44 个被引用模块（`runtime` / `dsn` / `imap-inbox` / `ingest` / `mcp-adapter` /
`nearfield-confirm` / `agents` / `serial-*` / `print-adapter` / `caldav-writer` / `asr` …），
合计 **50 个源文件**。未纳入：`src/backup.cjs`、`src/device-provisioning.cjs` —— 只被
`scripts/` 下的 CLI 使用，不在服务端/控制台的依赖图里；如要覆盖，需单独把它们加入 include。

## 3. 做法

### 3.1 集成门面的依赖注入按 `any` 处理

`ConsoleService` 的构造参数是一个 50+ 字段的注入袋（Fake/SMTP 邮件、虚拟/真板确认、
Mock/HTTP 模型、各种存储与目录）。为它逐个字段声明 typedef 收益低且易漂移，
本轮按「可替换实现」标注 `@param {any} [options]`，具体契约由各模块自身与调用点测试保证。
`AgentRuntime` 同理。

### 3.2 跨方法赋值的字段显式声明

TS 不分析构造函数之外的 `this.x = ...`，导致 `_initWorkspace()` 里创建的
`store/audit/risk/planner/runtime/...` 被推断成 `undefined`（290 个 TS2532 的主因）。
在类体顶部用 `/** @type {any} */ field;` 显式声明这些字段（无初始值，运行期不变）。

### 3.3 catch 变量统一收窄

`useUnknownInCatchVariables` 下 `catch (err)` 的 `err` 是 `unknown`。
逐处改写为：

```js
} catch (errRaw) { const err = /** @type {any} */ (errRaw);
```

只改绑定名与新增一行断言，块内原有 `err` 用法一律不动；共 66 处（`console-service` 35、
`server` 21、其余模块 10）。这是等价的：`errRaw` 与 `err` 是同一个对象。

### 3.4 `nodemailer` 的类型声明

`nodemailer` 未自带类型，`checkJs` 下 `require('nodemailer')` 报 TS7016。
新增 `types/nodemailer.d.ts`（`declare module 'nodemailer';`）并加入 include。
运行时行为不变，只为让可选依赖在类型层可用。

### 3.5 等价改写（逐条，均有测试兜底）

| 位置 | 改写 | 说明 |
|---|---|---|
| `auth` 的 18 处抛错 | `const err = new Error(m); err.code = c; throw err;` → `throw authError(m, c);` | 新增 `authError()`，返回同一个带 `code` 的 Error |
| `console-service` 两处展开 | `{ at: ..., ...result }` → `Object.assign({ at: ... }, result)`；`{ ok: true, ...exported, pruned }` → `Object.assign({ ok: true }, exported, { pruned })` | 保留原覆盖顺序 |
| `console-service` 草稿审计 | `next.operationHash.slice(0, 16)` → `/** @type {string} */ (next.operationHash).slice(0, 16)` | 纯断言 |
| `serial-nearfield` | `portPath.trim()` → `String(portPath).trim()`（2 处） | 入参已在函数首校验为非空字符串 |
| `asr` | `signTc3({ secretId, secretKey, ... })` → `String(secretId)` / `String(secretKey)` | 入参已校验非空字符串 |
| `caldav-writer` | `eventUrl(url, uid)` → `eventUrl(String(url), uid)` | 函数内部本就 `String(baseUrl)` |
| `agents` | `role` 在通过角色校验后落 `roleName` 局部变量 | 值相同，仅让 TS 在后续调用点收窄 |
| `smtp-mailer` / `board-human-confirm` / `imap-poller` / `mail-accounts` | `err.message` → `err instanceof Error ? err.message : String(err)` | 纯诊断文案；对 Error 实例完全等价 |

未改动：任何闸门、令牌、冻结、审计、白名单、密码学逻辑；导出、默认值、控制流均不变。

## 4. 验证

```bash
npm run lint             # 147 个文件语法通过 + 自定义危险模式扫描
npm run typecheck        # 0 error
npm run typecheck:strict # 0 error（50 个源文件）
npm test                 # 582 项：580 通过 + 2 跳过
npm run e2e              # 11/11
```

跳过项不变：真实 ClamAV 扫描、真实 Edge 渲染（环境门控）。

## 5. 边界

- 本轮只做类型标注，**不改变任何运行期校验**；闸门/令牌/溯源/沙箱的行为仍以测试为准。
- strict 覆盖的是服务端与业务链路；`src/backup.cjs` / `src/device-provisioning.cjs`
  仍是 `checkJs:false`（CLI 专用，未纳入）。
- `ConsoleService` / `AgentRuntime` 的注入袋是 `any`：类型检查覆盖方法体与跨模块调用，
  但不校验「传进来的具体实现是否满足契约」——那部分仍由各模块测试与运行时校验负责。
