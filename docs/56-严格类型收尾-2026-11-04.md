# strict typing 收尾轮（v0.47.1，2026-11-04）

> 本轮把 [47-软件剩余清单](47-软件剩余清单.md) §5 的最后一项非硬件欠账做完：
> `planner` / `tool-registry` / `model-boundary` / `sandbox`（连带 `capabilities`）纳入 `typecheck:strict`。
> **92 个类型错误 → 0**；运行时行为不变，测试口径不变。
> 验证：**463 项 Node 测试（461 通过 + 2 跳过）**、**11 项浏览器 E2E**、lint / typecheck / typecheck:strict 全过。

## 1. 范围

`tsconfig.strict.json` 的 include 从 6 个模块扩到 **11 个**：

| 模块 | 角色 |
|---|---|
| `faults` / `operation` / `audit-sign` / `ws63-protocol` / `guard` / `store` | v0.46–v0.47 已纳入 |
| `capabilities` | 能力分级表（单一事实源） |
| `sandbox` | 执行环境沙箱档案与校验 |
| `model-boundary` | 出站目标占位符 / 云侧输入装配 |
| `tool-registry` | 工具注册表（内置种子 + 自定义/MCP 叠加层） |
| `planner` | 带护栏的规划器（结构/溯源/委托/生成稿绑定） |

错误分布：`planner 38`、`tool-registry 34`、`model-boundary 12`、`sandbox 5`、`capabilities 3`。

## 2. 做法

- 全部用 **JSDoc typedef + 参数标注**，不引入 `.ts`、不改模块边界。
- **模型输出仍按不可信数据（`any`）处理**：`validatePlan(rawSteps)`、`resolveTargets(rawSteps)`
  显式标注 `any`，真正的约束仍在运行时校验里——类型只服务调用方，不替代校验。
- 公共结构（`ToolMeta` / `SandboxProfile` / `ToolDefinition` / `PlanStep` / `Finding`）
  各自文件内声明 typedef，跨文件靠结构化推断，不新增共享类型文件。

### 顺带修掉的一个真问题

`ToolRegistry.toolsForRole` 为了通过类型检查提取了 `policy.decide`，第一次实现丢了 `this`，
`PolicyEngine.decide` 立刻抛 `Cannot read properties of undefined (reading 'policies')` ——
被 `test/tool-registry.test.cjs`「Console 集成」用例当场抓住。
现改为 `policy.decide.bind(policy)`。这条记录在此，提醒后续重构：**方法提取必须保留接收者**。

### 等价改写（行为不变）

| 位置 | 改写 | 原因 |
|---|---|---|
| `sandbox.checkSandbox` | `if (profile.fsRead \|\| profile.fsWrite) { const f = ... }` → `const f = ...; if (f)` | 让 TS 对 `f` 收窄 |
| `planner.validatePlan` | 指令内邮箱/URL 匹配结果先落到 `string[]` 局部变量 | `match() \|\| []` 推断成 `never[]` |
| `planner.makePlan` | `authorizedToolList` 局部变量 | `Array.isArray` 的收窄不跨表达式 |
| `tool-registry.normalizeDefinition` | `const level = String(input.level ?? '')` | 非字符串仍会被 `LEVELS.has` 拒绝，语义不变 |
| `planner` 计划修正失败 | `err instanceof Error ? err.message : String(err)` | `useUnknownInCatchVariables` |

## 3. 边界

- strict 覆盖的是**安全核心 + 持久化 + 规划/工具链**；`console-service`、`server`、
  `auth`、`mailer` 等外围模块仍是 `checkJs: false`，全量 strict 属可选加固，不在本轮范围。
- 类型标注不改变任何运行期校验；闸门、令牌、溯源、沙箱的行为以测试为准。
- `bench.test.cjs` 有一条 10s 墙钟断言，在高负载（连续跑 tsc/eslint/全量测试）时观察到
  **1 次**偶发失败；单跑与随后 4 次全量均通过，记为已知 flake 面，未改断言。
