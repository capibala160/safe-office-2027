## 参考命题原文（不参赛，仅作设计约束）

> 华为命题原文（2026-10-15 逐字核对）：基于 OpenHarmony 6.0.0.1 Release 版本，围绕智慧办公场景中的智能体运行与数据处理过程，完成面向智慧办公场景设计并实现一个具备 Agent 安全防护与治理能力的解决方案；围绕办公智能体执行过程中的安全问题，设计一套适用于智慧办公场景的 Agent 安全运行机制。
>
> **口径**：本项目**不参加国创赛**，上述原文只作为需求/设计参考；实际底座以所选板卡与镜像为准（4.x/5.x/6.0.0.1），材料中写实际版本，不冒充 6.0.0.1。

## 一句话方案

让办公智能体在**可管控、可确认、可审计**的边界内干活：
**防护**（注入拦截 / 工具越权拒绝 / 数据外泄防控）+ **治理**（策略中心 / 全链路审计 / 风险评分 / 可视化）+ **物理锚点**（WS63 星闪近场确认，高危操作必须持有设备主动确认）+ **沙箱与模型边界**（执行环境独立一锁；机密正文不进云），用多场攻防演示说话。

## 口径纪律

1. **底座写实际版本**：用了 OH 4.x 就写 4.x，用了 5.x 写 5.x；**只有真跑过 6.0.0.1 才能写 6.0.0.1**。星闪节点当前用 **fbb_ws63（LiteOS，`ws63-liteos-app`）**，与主设备版本**分开写**；若改用 `ohos_ws63` 才写 OH 5.1.0 轻量系统
2. 只写做出且验证过的功能；未完成的标"设计中/规划中"
3. 系统层改造默认不做（走"应用层 + 系统应用层"）；不修厂商 BSP
4. 模型部署口径：**端云协同**——机密文档正文不进云侧模型（分级分流+审计留痕），安全策略全部在端侧
5. 时间纪律：项目服务于毕设/简历，不与考研冲刺抢时间；2027 秋开题前完成可演示版本即可
6. **`engineering-master` 边界（2026-10-14 用户界定）**：智能建造文档审查平台**仅作思路借鉴**——不复用其代码/文档/场景素材/命名；本项目演示场景与全部素材自建
